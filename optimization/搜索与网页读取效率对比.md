# OPT-001 搜索与网页读取效率对比

记录日期：2026-11-03。状态：待执行；目前没有A/B性能结论。

## 目标与两种方案

在取得相近质量和数量的可用资料前提下，比较端到端耗时、请求量和模型成本。

- A：搜索后直接并发读取前N条候选，再交给模型分析。
- B：搜索后先由模型根据标题、摘要、来源选择，再并发读取被选网页。

两种方案复用search_web、fetch_webpage的底层能力，不为实验重写抓取器。
工具仍可独立调用；实验编排、并发限额和模型选择后续实现。当前真实测试按候选顺序
读取到首个成功即停止，只验证能力，不作为A或B的基准测试。

## 实验要求

使用健康、法律等固定主题集合。记录搜索引擎及服务器配置、模型、并发上限、
候选条数、正文字符上限、下载上限、超时、连接复用与缓存条件。
分两组比较：固定同批候选URL以隔离搜索波动；完整在线搜索以评估真实用户耗时。
交替执行两种方案并重复多次，标记冷/热连接，不能只比较一次运行。

## 记录指标

| 指标 | 含义 |
| --- | --- |
| 搜索耗时/选择耗时/抓取耗时/总耗时 | 使用单调时钟计时，单位毫秒，分别报告中位数及P95 |
| 首份可用正文耗时 | 首次得到可用资料的等待时间，不等于全部任务完成时间 |
| 模型次数、输入/输出token与金额 | 使用实际计量及当时价格；HTTP下载本身不消耗模型token |
| HTTP次数、下载字节、失败数 | 包含重定向、超时及无效读取，不能只统计成功请求 |
| 有效来源数、相关性、权威性 | 记录人工评判方法；成功提取文本不等于资料有效 |

# 对话问题与附件读取（2026-11-06）

统一入口为POST /ppt-agent/v1/chat，原POST /ppt-agent/v1/files及独立上传路由、上传请求响应类型、旧测试已经移除。
这一步只接收、校验并提取附件内容，不将问题或附件交给模型，不根据问题筛选正文。
无附件时只确认消息已接收，返回JSON；同样不调用AI。每次最多一个附件；多文件支持尚未实现。

## Postman操作

运行根目录main.py后，请求默认地址：

```text
POST http://127.0.0.1:8000/ppt-agent/v1/chat
```

Body选择form-data：

| Key | 类型 | 示例及含义 |
| --- | --- | --- |
| message | Text | 请读取资料，后续用于生成健康饮食PPT。必填，去首尾空白后1–10000字符 |
| file | File | 选择真实文件；不是磁盘路径字符串，可选 |
| template_key | Text | 列表object_key原样回填，可选，1–1024字符；指定后真实下载并解析PPTX，不是URL |

不要手动填写Content-Type，由Postman生成multipart边界。附件支持TXT、MD、PDF、DOCX、XLSX、PPTX；统一作为参考资料，模板从独立资源列表选择。
不支持旧版DOC/XLS/PPT、带宏Office文件、图片附件或技能上传。TXT/MD支持UTF-8（含BOM）及带BOM的UTF-16。
只接受message和可选file/template_key，禁止额外字段、重复字段或多个附件。purpose已移除，继续传入会返回4xx（表单字段数量超限时400）。

正常响应HTTP 200、application/json。下面以文本附件举例，大小和正文按实际文件变化：

```json
{
  "message": "请读取资料",
  "template_key": null,
  "status": "attachment_read",
  "model_called": false,
  "retained": false,
  "template": null,
  "attachment": {
    "file_name": "资料.txt", "format": "txt", "size_bytes": 12,
    "content": {
      "blocks": [{"block_id": "b000001", "kind": "text", "text": "健康饮食", "location": "全文", "page": null, "sheet_name": null, "row_number": null, "cells": []}],
      "page_count": null, "pages_without_text": [], "warnings": []
    }
  }
}
```

attachment_read表示读取阶段结束，不等于已OCR或生成PPT。model_called固定false；retained固定false，没有跨请求取回接口。
block_id只在本次读取内编号，不是source_id，也不表示已经接入list/search/read资料工具。

不带附件时可以发送JSON，响应仍为JSON，不调用模型：

```json
{"message": "你好"}
```

未提供任何文件时status=message_received、attachment/template均null、model_called=false。template_key默认null，提供时不能为空，必须为OSS中真实PPTX对象标识。
仅上传附件时status=attachment_read；指定template_key会实际下载模板，只有模板时template_read，两份文件都提供时files_read。均不按message做AI分析。

## 模块与断点

```text
chat_routes.py：可选附件解析，所有分支统一JSON，不调用AI
  → chat_request_parser.py：收流、解析消息、校验元数据和大小
  → chat_form_parser.py：限制multipart并关闭临时句柄
  → chat_attachment_processing.py：组装配置、执行内容校验、选择读取器
  → domain/uploads：纯文件名、文本/PDF/Office包检查
  → integrations/documents/*_document_reader.py：逐格式真实提取
  → DocumentContent：正文块、位置及限制 → ChatReadResponse
```

建议在api/chat_attachment_processing.py的validate_and_read内打断点：检查attachment.format、字节数量和reader类型；进入reader.read查看解析。
外层result是统一内容结果。所有同步解析在线程中执行，避免直接堵塞异步HTTP循环。
DocumentReader协议不依赖HTTP/Settings/模型；读取器接收bytes和DocumentReadLimits，由调用方组装。
读取器关闭自己创建的文档/工作簿/原生句柄；文件流关闭归表单上下文。PDFium文字和图片渲染共享进程锁。

## 各格式实际读取范围

| 格式 | 读取结果 | 当前边界 |
| --- | --- | --- |
| TXT/MD | 一个全文块 | 不渲染Markdown，不按问题过滤 |
| PDF | 每个有文字页面一个块，真实页码 | 无文字页在pages_without_text列出；尚未OCR，不保证复杂分栏阅读顺序 |
| DOCX | 正文段落与顶层表格，保留交错顺序、表格行/单元格 | 不猜Word页码，不展开页眉页脚、批注、图片、嵌套表格 |
| XLSX | 按表/行读取，保留表名、行号、空单元格、公式文本 | 包含隐藏表并提示；不计算公式或读取缓存结果，不读取图表图片/样式 |
| PPTX | 实际幻灯片的文字、表格及组合内文字，真实幻灯片序号 | 不混入母版占位提示，不做模板角色/视觉分析；不读备注、图片OCR、图表数据、SmartArt |

warnings是固定能力提示，不是模型结论。内容为空仍可能200，须查看warnings和无文字页列表。
聊天上传的PPTX仅作为参考资料读取；设计模板从GET /ppt-agent/v1/templates选择，template_key已接实际下载和PPTX文字解析；模板结构/转换/渲染/视觉链路仍待后续接线。

## 校验、上限与错误

UPLOAD_MAX_FILE_BYTES默认20971520（20 MiB），范围1024–104857600；请求另允许64 KiB表单开销。
UPLOAD_MAX_UNCOMPRESSED_BYTES默认104857600，范围1024–1073741824；Office包最多5000条目，关键XML每份2 MiB。
Office包做CRC、展开量、核心XML/内容类型/根关系检查；拒绝加密/宏/异常路径，避免不同Office格式互相改名。
目前面向常见Transitional Open XML，不承诺Strict及所有第三方Office变体。
DOCUMENT_MAX_CHARACTERS默认200000（1–2000000）；DOCUMENT_MAX_BLOCKS默认5000（1–20000，含空单元）；DOCUMENT_MAX_CELLS默认100000（1–1000000，含空格）。
上述读取上限超出明确413，不截断后伪装全文。配置来自Settings，系统环境优先于.env，缺失取默认，空值无效。

错误形如：

```json
{"detail": {"code": "document_unreadable", "message": "Word正文无法读取，请检查DOCX结构是否完整。"}}
```

400：空文件、损坏文件、不可读取正文、无效文件名/表单；413：文件/展开/读取规模超限；415：格式或MIME不支持；422：缺字段、无效message；503：配置错误。
日志通过request_id/operation_id关联，记录开始、结束、失败和数量；不写正文、问题、文件名或底层异常原文。

不归档原文件，不建立正文缓存；Starlette可能使用系统临时文件，退出表单时关闭（含校验失败）。解析取消时由当前Starlette清理部分上传资源。
取消线程等待不会立即停止解析，底层线程结束时关闭资源；没有全系统并发配额或解析沙箱。文件校验不是杀毒或内容真实性验证。

## Postman手动验收

当前接口由使用者通过Postman与PyCharm断点验收，不保留独立HTTP自动化测试文件。2026-11-06用户确认本轮测试结束，当前附件读取与OSS模板读取小步已完成测试确认。下列步骤保留作复测说明，不表示每种格式、错误和限额均已逐项人工核对；此前自动化结果与本次用户确认分别记录。

1. 在PyCharm运行根目录main.py，确认服务启动；按上面的form-data表发送message、可选file和template_key。
2. 先用有已知正文的TXT文件验证：预期HTTP 200、JSON响应，blocks中能找到原文，model_called=false、retained=false。
3. 分别选择PDF、DOCX、XLSX和PPTX，核对正文及位置：PDF/PPT有真实页码；Word没有猜测页码；Excel有表名/行号，公式为文本。
4. PPTX作为参考资料读取实际页面文字；设计模板请另外按[模板资源列表说明](模板资源列表调试说明.md)查询。
5. 扫描PDF或无文字页查看pages_without_text和warnings；没有OCR结果时不能把空正文误认为全文已读。
6. 缺少message应返回422；空文件返回400；不支持格式返回415。若测试大小上限，可在.env临时调低对应配置并上传超限文件，预期413，测试后恢复配置。
7. 若要检查无附件聊天，改为Body → raw → JSON，发送{"message":"你好"}，预期JSON、status=message_received、attachment=null；这一分支也不调用模型，不需要模型配置。

断点建议：api/chat_attachment_processing.py的validate_and_read()和reader.read()，检查选中的读取器及返回的result。响应头X-Request-ID用于关联log目录中的请求日志。
无需创建Postman目录、集合或环境文件，直接在你自己的Postman中操作即可。

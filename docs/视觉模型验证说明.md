# GLM-5.3-Flash视觉输入验证

日期：2026-11-04。定位：独立的真实模型集成示例，不是离线单元测试，不新增Agent工具，尚未接入Harness模板分析。

## 运行

```powershell
uv run --locked --no-sync python -m examples.vision_model_demo
```

在项目.env配置：

```dotenv
LLM_VISION_MODEL=glm-5.3-flash
```

代理地址和密钥复用已有LLM_BASE_URL、LLM_API_KEY，不修改默认文本模型。系统环境优先于.env，未配置视觉模型时默认glm-5.3-flash，不能留空。真实调用会消耗供应商额度；max_retries=0，不自动重试。例子默认输出预算4096 token、HTTP等待超时120秒，可用--max-tokens和--timeout修改；不沿用普通文本对话的输出预算，以免推理占满短额度。

指定其他图片：

```powershell
uv run --locked --no-sync python -m examples.vision_model_demo --image "E:/test/ppt-agent/data/vision-demo/template-thumbnail.png" --max-tokens 4096 --timeout 120
```

PyCharm用模块examples.vision_model_demo运行，在`response = await model.ainvoke([message])`打断点。不要把包含base64图片的消息或完整Settings复制到日志。示例没有启用项目DEBUG日志初始化，避免把第三方请求细节作为测试输出。

## 图片和提示词

不传--image时，读取data/vision-demo/下唯一一张PNG/JPEG（不递归，忽略JSON等非图片文件）。无图片或多张图片时明确报错，可用--image选择。只读取用户图片，不从PPTX提取缩略图、不生成或覆盖图片。当前用户放入template-thumbnail.png，该名称只是文件名，不代表程序生成的PPT缩略图。

提示词独立位于prompts/vision_template_analysis.md，可直接编辑。要求识别可读文字、主要配色与布局、页面角色及不确定内容。只发送提示词与图片，不发送模板结构或预期答案。读取文字后人工对照输入图片及已有结构，避免把模型能根据文本猜答案误认为图片能力。

通过ChatOpenAI的Chat Completions图片内容块发送：text + image_url；图片转为data:image/jpeg;base64,...，代理不需要访问用户本机路径。不把PPTX本身直接当图片发送。http_socket_options=()保留httpx默认系统代理行为；未更改项目其他模型连接策略。

## 历史验证结论与限制

注意：用户后续确认该内嵌缩略图与当前PPT所有页面不对应。以下历史结果只证明实际发送图片的识别，不证明当前PPT页识别正确。2026-11-05已移除缩略图提取，改为用户截图输入；新图片由用户重新运行核对，未标记识别通过。

历史调用成功，耗时50.8秒。供应商返回input_tokens=418、output_tokens=1693、total_tokens=2111，其中reasoning=1176。以实际usage为准，不将token数换算成未经核实的价格。

人工核对：

| 内容 | 图片依据与模型结果 | 结论 |
| --- | --- | --- |
| 大标题 | 识别到XXXXX | 正确 |
| 主要布局 | 白底、左侧蓝色调建筑照片、右侧蓝色标题横条 | 基本正确 |
| 页面角色 | 根据大标题、汇报人及公司标识判断为封面 | 合理，仍是判断而非PPT结构事实 |
| 左上公司名 | 识别为智邮科技 | 正确 |
| 右上公司名 | 图片为智邮科技，模型读成超邮科技 | 错误 |
| 极小或低对比文字 | 多项标记无法确认，口号等有不确定字 | 未完整识别，不能宣称OCR准确 |

这次确认的是当前代理和模型名称支持这一张图片输入，并能做基本布局描述；不是所有页面、所有分辨率或任意版式的准确率证明。图中文字里的XXXXX是视觉上类似占位文本，不等于发现正式PPT占位符。仅凭图片不能确定对象编号、可编辑性、母版和继承关系。

## 输出文件字段

data/vision-demo/vision-result.json保存本次回答，重跑会覆盖此示例结果；data/已在Git忽略规则中。

| 字段 | 说明 |
| --- | --- |
| model | 本次实际调用的模型名 |
| image_name | 输入图片文件名，不保存本机绝对路径 |
| elapsed_seconds | 图片请求至收到回答的耗时秒数，不是完整Agent任务耗时 |
| usage | LangChain规范化的供应商token用量；供应商未返回时可为空 |
| answer | 模型的完整可见回答，不保存隐藏推理；不是自动核验后的正确答案 |

不保存密钥、代理地址、请求base64或SDK完整响应。原始图片也单独保存在本地data中。API超时/连接失败/HTTP错误输出简明原因，不自动重试；没有可见文本时明确报错，不伪装识别成功。

## 后续边界

当前不新增渲染工具、不改inspect_template，不自动把模板上传给模型，也不自动让Agent调用视觉。后续Harness模板分析可采用LLM_VISION_MODEL，但仍需逐页渲染、高分辨率图片、结构与视觉联合定位等接线与样本测试。视觉判断不替代人工反馈或事实/来源核验。

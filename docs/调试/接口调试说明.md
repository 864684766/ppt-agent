# 对话接口调试（2026-11-24）

启动 `uv run --locked --no-sync python main.py`；对话仅保留SSE接口。

## 资料收集和多轮补充（SSE）

`POST http://127.0.0.1:8000/ppt-agent/v1/chat/stream` 接收 JSON 或 multipart/form-data。Postman 中 Body 选择 raw / JSON，例如 `{"message":"介绍一下黄芪。"}`；可选请求头 `Accept: text/event-stream`。也可用 PowerShell：

```powershell
curl.exe -N -X POST http://127.0.0.1:8000/ppt-agent/v1/chat/stream -H "Content-Type: application/json" -d '{"message":"介绍一下黄芪。"}'
```

响应为 text/event-stream：`start` 的 data 含 task_id；`progress` 含 task_id、stage、message，stage 包括 analyze、file、template、search、review、read_webpage、extract、summarize，只有实际执行时才发送；`result` 包含完整的 ChatReadResponse JSON，status=awaiting_user 时问题在 waiting_question；`error` 含 task_id、code、message，不包含异常详情。每15秒无事件时可能发送 `: heartbeat` 注释。请求开始流之前的字段错误仍使用普通HTTP错误；流开始后出错用error事件，HTTP状态不能再变更。

`result` 在已有相关要点且模型生成分页大纲时返回 `status=completed` 和 `outline`，补充建议保留在 `report.issues`。若最终模型调用超时、连接失败、输出超限或返回无效结构，且已有可用要点，接口会按提炼顺序编排一份草稿写入 `outline`，并以 `status=interrupted` 和 `outline_error` 保留故障分类。需求待澄清或没有形成可用大纲时，返回 `awaiting_user`，补充资料的原因见 `waiting_question`。

`outline.slides` 按列表顺序展示页面，`summary` 和每条大纲要点的 `point_ids` 均可通过 `summary_inputs` 反查网页或文件块来源。仅分析文件时 `sources` 为空。结果也包含 `analysis`、`report`、`attachment_analyzed` 和 `attachment_file_name`。补充消息可以直接发到同一路由，携带 previous_task_id。客户端断开时服务取消正在等待的任务，已在线程中执行的文件解析或 OCR 可能继续运行。服务发送 `X-Accel-Buffering: no`，代理实际是否缓冲取决于它的配置。检查点保存在当前服务进程内存中，重启后失效。

真实验证：2026-11-24 使用本地Uvicorn、真实HTTP连接、真实模型及搜索服务，临时限制搜索1轮/读取1页；0.1秒收到start、任务完成前多次收到progress，约66.9秒收到result（awaiting_user），最终JSON解析通过。该验证未覆盖实际浏览器断线、反向代理及multipart文件。


`LLM_SHOW_THINKING` 可在本机.env设置，默认false；true时/chat/stream会将LangChain标准reasoning内容块按 `event: thinking` 发送，data含task_id和text。开关只决定是否传输可获得的推理内容，不开启模型推理，不保证供应商或适配器提供该内容，也不控制输出token。当前兼容适配器会把服务返回的reasoning_content转换为LangChain标准reasoning块；其他服务如果没有提供标准块或该字段，开启后仍可能没有thinking事件。推理内容不会写入应用日志或最终JSON；每段均属于模型输出，客户端应作为文本而非指令处理。修改后重启服务；系统环境变量优先于.env。

2026-11-24适配前真实验证：临时启用LLM_SHOW_THINKING=true，使用当前千帆模型通过真实HTTP执行一次/chat/stream，返回200、progress和最终result（awaiting_user），未产生thinking事件，符合当前ChatOpenAI未保留该服务推理字段的已知限制；本次未验证其他供应商。

断点：api/routes/chat_stream_routes.py → api/chat/chat_stream.py → workflows/materials/material_collection_workflow.py（analyze、file/web、summarize、finalize、ask）。旧非流式 POST /ppt-agent/v1/chat 已删除；客户端请使用 /ppt-agent/v1/chat/stream。

2026-11-24兼容适配后真实验证：使用当前千帆模型和真实HTTP访问/chat/stream，返回200，依次收到start、progress、thinking及最终result（awaiting_user）；验证期间只统计thinking数量，没有记录推理内容。旧非流式/chat返回404。

### 继续上一轮

在第一轮的 SSE result 中复制 task_id。第二轮仍向同一 URL 发送 JSON，例如以下请求。

```json
{"previous_task_id":"替换为真实的32位task_id","message":"补充蜀汉和东吴"}
```

每轮返回新的 task_id。继续补充时传最新一轮编号。历史提炼要点及网页来源与本轮结果一起编排。文件来源编号可通过 file_sources 查文件名。上一轮编号只在本机服务的当前进程内有效，找不到编号时返回 SSE error，code 为 previous_task_not_found。保持同一服务进程处理两轮。

真实接口复测以“介绍一下三国历史”为首轮问题。Tavily 返回的 5 个候选全部通过检查，配置仅允许读取 1 页，首选网页超时后因没有正文要点返回补充问题。同一路由携带首轮编号追加蜀汉和东吴，成功读取 1 页并提炼 8 条要点，达到网页读取上限后进入大纲编排。最终模型超时，接口返回 2 页可追溯草稿。另用离线回归验证第一轮与第二轮都有要点时，新版大纲可引用两轮来源。

## 上传文件测试

在 Postman 向上述地址发送 POST 请求，Body 选 form-data。在 `message` 文本字段填“根据这个文件分析，给我一个PPT”，在 `file` 字段选择 DOCX 等支持的文件。Postman 会为 multipart 请求生成边界。检查 `start`、`analyze`、`file` 进度和 `result`，以及 `analysis.plan.source_mode=file`、`attachment_analyzed=true` 和 `summary` 中的整理要点。附件提炼出相关要点即可编排大纲，文件名称可通过 `file_sources` 查询。没有大纲时查看 `waiting_question` 或 `report` 中的原因。

不上传文件时，JSON 示例 `{"message":"帮我做一个PPT。"}` 可能因主题不明确返回 awaiting_user 和可自由输入的 waiting_question。网页示例 `{"message":"搜索健康饮食资料，制作PPT。"}` 应观察 search、review、read_webpage 等实际进度；搜索结果取决于外部服务。续轮上传资料时，在同一个 form-data 中加 previous_task_id。

验收大纲时检查 `outline.title`、页面顺序、每页标题和要点，以及 `point_ids` 与 `summary_inputs` 的对应关系。遇到 `awaiting_user` 时查看 `report.issues` 和 `waiting_question`。页数随资料和用户要求变化，建议核对覆盖范围和来源。

用户指定网址时，网页研究直接读取该网址，单页模型可从真实链接中选择最多 10 个同站相关链接。`RESEARCH_MAX_WEB_PAGES` 限制读取次数，包含失败的读取。未读的补充链接填入 `report.web.issues` 的 `followup_unread`。指定网页已读取且内容足够时，可以生成大纲。`provided_pages_exhausted` 表示指定网址及已选链接全部处理完毕，资料仍未达到充分性条件。读取失败或截断见 `report.web.issues`。

每个网页最多读取 50,000 字符，分段提炼后的要点沿用同一网页来源编号，超出读取上限时报告截断。最终生成大纲时，模型返回分组、标题和引用编号，程序根据编号填入资料要点。

汇总按紧凑 JSON 字符数估算分批，预算取 `LLM_MAX_TOKENS` 的数值与 12,000 的较小值。思考展示关闭时最多 3 批并发，开启时逐批处理。`material_batches_start`、`material_batch_start`、`material_batch_completed` 和 `material_final_start` 记录批次、要点数量和耗时。模型给出可解析的最终结果时，`material_final_result` 记录要点、页数和内容问题数量。中间批次每次最多等待 `LLM_TIMEOUT_SECONDS`，最终调用每次最多等待 60 秒或 `LLM_TIMEOUT_SECONDS`，取两者较小值。聊天汇总包含分批、重试和最终调用，总时限取 120 秒与 `LLM_TIMEOUT_SECONDS` 两倍的较小值。网页读取及提炼单独计时。SSE 收到 HTTP 200 后，请以 `result` 或 `error` 确认任务结果。

开放搜索使用 RESEARCH_TARGET_SOURCE_COUNT 控制何时结束收集。获得一份可用资料也可以返回大纲，缺失的子主题、指定来源或读取失败在 report 中说明。标题或摘要覆盖任一相关子主题即可进入正式候选，仍遵守用户明确限定。

只生成文字汇总时，最终模型输出超限会使用 `materials/material_summary_retry.md` 精简后重试一次。最终大纲调用遇到超时、连接失败或输出超限时，已有可用要点时，程序可编排草稿。

网页处理失败时，notice和report.web.issues说明已知阶段及安全错误类别。网页分段遇模型服务5xx时只重试失败分段一次；重试仍失败时保留已完成分段及网页来源，交上层尝试生成部分大纲，报告标明网页处理未完成。其他分段异常也会保留同组和先前组成功的内容；取消仍正常传播。没有已完成要点时返回中断，outline_error为null表示尚未执行大纲生成。可携带本轮 task_id 作为 previous_task_id 再次补充资料。

中间批次超时或连接失败时最多重试当前批次一次，日志记录 `material_model_retry` 和安全原因。重试也计入整次汇总的时间限制。

资料汇总内部向模型发送短要点和来源编号，结果通过范围校验后恢复为原始point_id；HTTP结构和来源追溯不变。模型推理可能计入LLM_MAX_TOKENS，展示thinking开关不能控制模型是否推理；最终长度超限仍可能中断。

浏览器备用读取：Windows安装Microsoft Edge并在.env设置WEBPAGE_BROWSER_FALLBACK=true（默认）；重启后通过POST /ppt-agent/v1/chat/stream提交网页地址。HTTP返回401/403或空正文时自动尝试独立无界面Edge；查看日志webpage_browser_fallback和browser_webpage_result。页面标题、正文和验证码需人工核对；不共享浏览器登录状态。运行真实验证：uv run --locked python -m pytest tests/test_browser_webpage_reader.py -s。

网页模型分段提炼超时或连接失败时重试当前段一次，日志event=webpage_extraction_retry；再次失败记录webpage_segment_incomplete并返回interrupted。先前成功分段可在summary_inputs查看，但页面不完整；当前HTTP尚不支持从失败段恢复。

Tavily搜索：本机.env设置WEB_SEARCH_PROVIDER=tavily并填写TAVILY_API_KEY，重启服务；SearXNG可改为searxng并配置SEARXNG_BASE_URL。仅在需求分析选择联网搜索时调用；直接提供网址的现有分支不会自动搜索。真实搜索工具测试：uv run --locked python -m pytest tests/test_tavily_search.py -s；basic搜索消耗额度，结果摘要需另行读取网页。

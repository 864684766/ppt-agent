## 资料收集首轮（SSE，2026-11-25）

`POST http://127.0.0.1:8000/ppt-agent/v1/chat/stream` 接收 JSON 或 multipart/form-data。Postman 中 Body 选择 raw / JSON，例如 `{"message":"介绍一下黄芪。"}`；可选请求头 `Accept: text/event-stream`。也可用 PowerShell：

```powershell
curl.exe -N -X POST http://127.0.0.1:8000/ppt-agent/v1/chat/stream -H "Content-Type: application/json" -d '{"message":"介绍一下黄芪。"}'
```

响应为 text/event-stream：`start` 的 data 含 task_id；`progress` 含 task_id、stage、message，stage 包括 analyze、file、template、search、review、read_webpage、extract、summarize，只有实际执行时才发送；`result` 包含完整的 ChatReadResponse JSON，status=awaiting_user 时问题在 waiting_question；`error` 含 task_id、code、message，不包含异常详情。每15秒无事件时可能发送 `: heartbeat` 注释。请求开始流之前的字段错误仍使用普通HTTP错误；流开始后出错用error事件，HTTP状态不能再变更。

`result` 在资料达到条件且生成成功时包含分页PPT大纲 outline；等待询问或生成失败时 outline 为 null。结果包含 analysis、summary、outline、outline_error、summary_inputs、sources、report、waiting_question、attachment_analyzed 和 attachment_file_name。outline.slides按列表顺序展示页面，每条bullet的point_ids通过summary_inputs反查来源；outline_error仅在大纲生成失败时提供安全分类。summary的point_ids通过summary_inputs反查网页或文件块来源；仅文件分析时sources为空。status=interrupted时查看notice与analysis或report，不能当作资料不足。HTTP回答接口尚未接入；可选思考事件见下方配置。客户端断开时服务取消正在等待的任务；文件解析或OCR若已在线程中执行，取消等待不保证立刻停止线程。中间代理可能缓冲响应；服务发送X-Accel-Buffering: no，但实际代理配置仍需验证。检查点保存在当前服务进程内存中，重启后失效。

真实验证：2026-11-24 使用本地Uvicorn、真实HTTP连接、真实模型及搜索服务，临时限制搜索1轮/读取1页；0.1秒收到start、任务完成前多次收到progress，约66.9秒收到result（awaiting_user），最终JSON解析通过。该验证未覆盖实际浏览器断线、反向代理及multipart文件。


`LLM_SHOW_THINKING` 可在本机.env设置，默认false；true时/chat/stream会将LangChain标准reasoning内容块按 `event: thinking` 发送，data含task_id和text。开关只决定是否传输可获得的推理内容，不开启模型推理，不保证供应商或适配器提供该内容，也不控制输出token。当前兼容适配器会把服务返回的reasoning_content转换为LangChain标准reasoning块；其他服务如果没有提供标准块或该字段，开启后仍可能没有thinking事件。推理内容不会写入应用日志或最终JSON；每段均属于模型输出，客户端应作为文本而非指令处理。修改后重启服务；系统环境变量优先于.env。

## 上传文件测试

Postman 选择 POST 和上述地址，Body 选择 form-data：`message` 选择 Text，填“根据这个文件分析，给我一个PPT”；`file` 选择 File 并选择 DOCX 等支持的文件。不要手写 multipart Content-Type，Postman 会生成边界。预期收到 start、analyze 和 file 进度及 result；检查 analysis.plan.source_mode 为 file、attachment_analyzed 为 true、sources 为空，summary 为整理要点；来源达到目标且无明确缺口时，outline 为分页大纲。资料不足时 status 为 awaiting_user，waiting_question 提供原因和选项。原始文件字节及正文不在结果中返回；分析失败可能返回 interrupted。

不上传文件时，JSON 示例 `{"message":"帮我做一个PPT。"}` 可能因主题不明确返回 awaiting_user 和可自由输入的 waiting_question。网页示例 `{"message":"搜索健康饮食资料，制作PPT。"}` 应观察 search、review、read_webpage 等实际进度；搜索结果取决于外部服务。HTTP 回答及补充文件恢复尚未接入。

大纲生成验收：在 `.env` 把 RESEARCH_TARGET_SOURCE_COUNT 按测试需要设为1后重启服务，使用有内容的文件测试（测试完恢复原配置）。状态 completed 表示最终汇总及大纲生成成功；检查 outline.title、slides 顺序、每页 title 和 bullets，以及 point_ids 与 summary_inputs 的关联。若结果 insufficient/awaiting_user，先检查来源目标与 report.issues；最终汇总模型失败返回 interrupted、outline=null 和 outline_error。8–12页仅是提示词参考，不为凑数编造内容，结果需人工核对。

用户提供网址：例如 message 为“根据这份网页资料，读取其中的内容，帮我做一个PPT。http://dg.cnsoc.org/newslist_0402_1.htm”。网页研究先直接读取提供的网址，不使用搜索引擎扩展；单页模型从真实链接中选择最多10个相关链接，并仅跟进同站链接。读取总次数受 RESEARCH_MAX_WEB_PAGES 限制，包含失败；未读取完选中链接时报告 followup_unread 并询问。停止原因 provided_pages_exhausted 表示提供的网址及已选择的链接处理完毕但仍未达充分性条件，失败或截断见 report.web.issues。静态HTML读取不会执行脚本，也不能保证模型选全链接或网页内容正确。

网页长文读取：每页最多取50000字符，再按3000字符逐段调用网页提炼并合并要点，来源仍是同一网页；超过50000字符或网页无法返回全文时仍可能不完整，报告截断。读取多段会增加模型调用和耗时。最终汇总一次返回问题和可选大纲；数据量过多时之前仍会分批压缩。

耗时排查：用户直接提供网址时，网页阶段逐篇提炼并将内容检查交给上层，不再对相同要点汇总两次。汇总会按输出预算分批；思考展示关闭时最多3批并发，开启时串行以避免文字混杂。日志 material_batches_start、material_batch_start、material_batch_completed 可查看批次及耗时，不含正文。每次汇总模型调用的总时长上限为 LLM_TIMEOUT_SECONDS，所有批次和最终汇总共用4倍该值的时限；超时返回 interrupted，outline_error=model_timeout，之前提炼资料保留。该时限不包括网页读取和网页单页模型，因此不是整个请求的时限。SSE HTTP 200只说明流已建立，完成须等待result或error；thinking文本会增加响应字节。

如果来源数明显不足或用户指定网站有已选链接未读/读取失败，最终汇总只请求资料与问题，不要求生成大纲；这样不会因生成暂不能使用的大纲增加输出。是否询问仍由程序检查真实来源数量和问题决定。

最终汇总输出超限时，同一Agent会将 materials/material_summary_retry.md 追加到原提示词并最多重试一次；普通请求不会发送该重试提示。它要求优先保留用户明确页数，无法满足时报告问题；当前尚未程序化校验自然语言页数，结果仍需人工核对。

# 对话接口调试（2026-11-24）

启动 `uv run --locked --no-sync python main.py`，在 Postman 发送：

```text
POST http://127.0.0.1:8000/ppt-agent/v1/chat
Content-Type: application/json
```

Body 选择 raw / JSON：

```json
{"message":"查找中国居民膳食指南2022关于平衡饮食的资料。"}
```

也可选择 form-data：message 为 Text，file 为可选 File，template_key 为可选 Text；不要手动填写 Content-Type 或传 purpose。template_key 使用模板列表的 object_key。

接口会联网搜索和调用模型，可能需要几分钟，确保 Postman 等待时间足够。HTTP 200 中 status 为 completed、awaiting_user 或 interrupted；research 包含 summary、sources、page_extractions、report 和 waiting_question。task_id 为本次任务编号。attachment 为附件解析结果，attachment_analyzed=false 表示附件未参与网页研究。未上传附件时为 null。

awaiting_user 表示工作流暂停并返回询问；HTTP 回答接口尚未实现。检查点仅在当前单进程内存中，服务重启后丢失。interrupted 表示模型检查未完成；要点和报告须结合 stop_reason 阅读。不要将模型判断视为已核实事实或最终大纲。当前每次请求都会搜索；仅使用文件分析尚未接入。

模型与搜索配置来自本地 .env：LLM_BASE_URL、LLM_API_KEY、LLM_OUTLINE_MODEL（空时回退 LLM_MODEL）、SEARXNG_BASE_URL；RESEARCH_* 控制收集数量和上限。网页研究的输出预算为 max(LLM_MAX_TOKENS, 4096)。初始化配置不正确返回503，研究调用失败返回502；附件与模板错误按各自错误代码返回。

断点：api/routes/chat_routes.py 的 chat → api/web_research_runtime.py 的 get_workflow → workflows/web_research_workflow.py 的 run、_fetch、_summarize、_ask。健康检查为 GET /health，模板列表为 GET /ppt-agent/v1/templates。日志不记录资料正文和密钥。

2026-11-24以真实模型、搜索服务与ASGI HTTP请求验证一次：HTTP 200、awaiting_user，检查点中的问题与响应一致；该次网页返回403，无可用正文。附件组合、成功汇总和用户回答接口未在该次HTTP验证中覆盖。

## 流式网页研究（SSE，2026-11-24）

`POST http://127.0.0.1:8000/ppt-agent/v1/chat/stream` 接收与 `/chat` 相同的 JSON 或 multipart/form-data。Postman 中 Body 选择 raw / JSON，例如 `{"message":"介绍一下黄芪。"}`；可选请求头 `Accept: text/event-stream`。也可用 PowerShell：

```powershell
curl.exe -N -X POST http://127.0.0.1:8000/ppt-agent/v1/chat/stream -H "Content-Type: application/json" -d '{"message":"介绍一下黄芪。"}'
```

响应为 text/event-stream：`start` 的 data 含 task_id；`progress` 含 task_id、stage、message，stage 包括 attachment、template、search、review、read_webpage、extract、summarize，只有实际执行时才发送；`result` 包含与普通 `/chat` 相同的完整JSON，status=awaiting_user 时问题在 research.waiting_question；`error` 含 task_id、code、message，不包含异常详情。每15秒无事件时可能发送 `: heartbeat` 注释。请求开始流之前的字段错误仍使用普通HTTP错误；流开始后出错用error事件，HTTP状态不能再变更。

`result` 是网页资料整理结果，尚非PPT大纲；附件只解析未交模型。HTTP回答接口和模型思考内容流均未接入。客户端断开时服务取消正在等待的任务；文件解析或OCR若已在线程中执行，取消等待不保证立刻停止线程。中间代理可能缓冲响应；服务发送X-Accel-Buffering: no，但实际代理配置仍需验证。检查点保存在当前服务进程内存中，重启后失效。

真实验证：2026-11-24 使用本地Uvicorn、真实HTTP连接、真实模型及搜索服务，临时限制搜索1轮/读取1页；0.1秒收到start、任务完成前多次收到progress，约66.9秒收到result（awaiting_user），最终JSON解析通过。该验证未覆盖实际浏览器断线、反向代理及multipart文件。

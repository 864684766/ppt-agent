# 资料提炼与汇总测试

以下测试均使用 `.env` 配置的真实模型，发送测试内容并消耗模型额度；结果的准确性、去重和来源需要人工核对。测试进程读取系统环境变量优先于 `.env`。

1. `uv run pytest tests/test_file_extraction_agent.py -s`：在测试文件内选择本机文件路径和相应问题；当前路径是用户选择的 `data/test_file/test3.pdf`。检查解析警告、`status`、`points` 和块编号。DOC还依赖Gotenberg；PDF无文字页可能需要OCR。大文件会多次调用模型，中断可能返回部分结果和恢复编号。
2. `uv run pytest tests/test_research_workflow.py -s`：调用真实模型、所选搜索供应商及网页服务。检查搜索候选是否相关、网页提炼要点及来源、汇总和询问；测试通过不等于信息可靠或找到结果。
3. `uv run pytest tests/test_material_summary_agent.py -s`：用测试内构造的网页与文件要点调用真实模型，检查相同内容是否合并、`point_ids`及实际来源是否同时包含网页和文件。它不真实读取网页或文件，也不代表聊天接口已接入多来源流程。
4. `uv run pytest tests/test_material_collection_workflow.py -s`：当前使用真实模型和本地 `test6.docx` 验证仅文件分析，并在不足时以 `end_conversation` 验证内存询问恢复；应检查网页阶段未执行、文件报告、汇总和问题。可在测试内修改文件和问题，并同步修改预期分支；模型中断会使测试失败，输出需人工核查。

资料工作流现在先输出需求分析计划。测试第4项当前预期 `source_mode=file`；可按需修改问题并调整断言，分别检查仅文件、仅网页和先文件后网页。`allow_web=False` 是禁止联网的明确约束。需求不明确时返回 `awaiting_user` 和 `waiting_question`；使用同一工作流实例、线程编号与问题编号调用 `answer` 后重新分析文字回答。缺少文件时可以询问，但回答中上传文件后恢复尚未实现。分析失败时应返回 `interrupted` 和 `analysis.error_code`，不会进入资料不足询问。

聊天入口已接入资料收集和汇总的首轮流程；回答接口及补充资料后恢复尚未接入。HTTP入口由用户按对话附件调试说明使用Postman验收。

只检查项目测试能否被发现：`uv run pytest tests --collect-only -q`。直接在仓库根目录收集全部测试还会扫描技能目录内独立项目，后者可能需要独立依赖，不代表主项目测试导入失败。

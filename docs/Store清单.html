Store 与结构化状态清单

概念设计、字段说明和第一阶段的保存方式

本清单是设计草案，不代表这些 Store 或数据库已经实现。第一阶段以单进程内存保存结构化运行状态、以本地文件保存上传和生成文件；重启后不承诺恢复内存状态。表中的名称是建议逻辑分类，不要求每项都实现为独立类或数据库表。

已实现的数据契约：资料目录快照（2026-11-02）

MaterialSummary 定义在 models/materials/material_source.py，MaterialPage 定义在 models/materials/material_query_results.py；类型创建方/使用方索引见 models/README.md，目录工具输入与公开输出集中在 models/materials/list_materials_contract.py；检索工具输入与公开输出集中在 models/materials/search_materials_contract.py，内部检索结果同样在 material_query_results.py；实体详细校验放在 validators/materials/material_metadata_validator.py，由实体构造后调用；此次仅调整定义位置，字段不变。MaterialSummary 是宿主提供的不可变资料摘要，不是已落地的数据库表或完整 Source/Citation Store。每条包含 project_id（内部绑定）、source_id（项目内唯一）、name、origin（uploaded/web）、format、status（pending/ready/failed）、version、url（网页必填，上传资料为 None）、page_count（未知为 None）。模板、技能和其他项目资料不属于本项目目录；登记方按用途提供对象。

MaterialPage 包含 items、total、next_offset；total 为筛选后总数，偏移从 0 开始，末页 next_offset 为 None。工具对外隐藏 project_id，仅选择公开字段。创建工具时复制输入序列，在同一快照中分页稳定；宿主更新后需重建工具。没有新增全局 Store、数据库或目录扫描，也未接入上传登记；本次测试数据仅存在测试进程内。运行时状态与持久化仍按后续任务实现。

已确认待实现：真实上传资料如何进入目录（2026-11-02）

真实运行使用与测试相同的MaterialSummary类型，但字段值来自上传和解析的实际结果。样本只是手动构造，正式数据由登记模块构造；不是把文件转成“测试数据”。当前只实现了接收目录快照的工具，以下上传、登记及内存目录仍待开发。

  1. 用户按“业务资料”用途上传文件；后端确定所属项目、分配source_id、保存原文件到本地磁盘。
  2. 读取实际名称和格式等元数据，构造MaterialSummary并加入当前项目的进程内存资料目录。先标记pending，未知page_count为None；project_id不由模型选择。
  3. 解析文本，扫描件需要时使用本机OCR。成功后创建新的不可变摘要替换目录记录，标记ready并填入可获得页数；失败标记failed。文件上传成功不等于正文解析成功。
  4. 正文和原页/文本块定位按source_id及版本单独关联保存，MaterialSummary只保留目录摘要，不包含正文或本机路径。
  5. 宿主取得当前项目目录快照，传给create_list_materials_tool。工具查询后只返回允许公开的字段。
  6. 目录新增或解析状态更新后，宿主需重建工具供后续调用使用。旧工具不会自动看到新增记录；同一轮分页保持同一快照，避免位置漂移。

模板、技能和未关联历史文件不混入业务资料目录。第一阶段结构化目录保存在内存，原文件保存在磁盘；不要求先建数据库，也不承诺进程重启后恢复目录。后续网页正文抓取成功并登记时也构造相同资料摘要，origin为web并保留原URL。

模型定义位置见数据模型索引；调用与打印结果见第二个工具调试说明。本轮没有实现文件上传、OCR或持久化。

2. LangGraph 中的几个概念

概念职责与本项目的关系
Graph State一次工作流当前的结构化状态，由图节点读取和更新。保存或引用当前大纲、模板映射、问题和任务状态；应避免在多个位置维护冲突的权威副本。
Checkpointer保存线程的图状态快照，用于中断恢复等。第一阶段可用内存检查点支持进程内暂停；跨重启持久化后续引入，具体方案待开发验证。
LangGraph Store可供不同线程按命名空间和键访问的数据存储，适合跨线程共享数据。不是 Graph State 或 Checkpointer 的同义词。当前不强制引入；仅当确有跨线程共享记忆等需求时评估。
文件存储保存模板、原始资料、PPTX、预览等文件。第一阶段本地目录；图状态只存文件标识、路径或元数据，不放大型二进制内容。
Harness 会话存储Harness 自己管理的会话与运行资源。与项目状态分开；不把 Harness 会话当作已确认大纲或模板映射的权威来源。

3. 设计约束

  • 清单是逻辑视图：实现时可以合并为少量内存仓储和图状态，避免为每一行提前引入独立基础设施。
  • 以项目 ID、任务 ID 和版本关联数据；确认后的大纲与模板映射作为生成任务输入快照。并发修改须检测版本冲突。
  • 模型、工具或子智能体的输出先由后端校验，再进入项目状态；人工确认是显式状态变更。
  • 第一阶段文件可能留在磁盘，但对应项目索引和会话存在内存中，进程重启不保证重新发现或恢复。
  • 后续引入数据库和持久化检查点时，再定义表结构、迁移、保留期限和恢复策略；不把当前字段草案当作已冻结数据库设计。

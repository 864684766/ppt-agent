Store 与结构化状态清单

概念设计、字段说明和第一阶段的保存方式

本清单是设计草案，不代表这些 Store 或数据库已经实现。第一阶段以单进程内存保存结构化运行状态、以本地文件保存上传和生成文件；重启后不承诺恢复内存状态。表中的名称是建议逻辑分类，不要求每项都实现为独立类或数据库表。

2. LangGraph 中的几个概念

概念职责与本项目的关系
Graph State一次工作流当前的结构化状态，由图节点读取和更新。保存或引用当前大纲、模板映射、问题和任务状态；应避免在多个位置维护冲突的权威副本。
Checkpointer保存线程的图状态快照，用于中断恢复等。第一阶段可用内存检查点支持进程内暂停；跨重启持久化后续引入，具体方案待开发验证。
LangGraph Store可供不同线程按命名空间和键访问的数据存储，适合跨线程共享数据。不是 Graph State 或 Checkpointer 的同义词。当前不强制引入；仅当确有跨线程共享记忆等需求时评估。
文件存储保存模板、原始资料、PPTX、预览等文件。第一阶段本地目录；图状态只存文件标识、路径或元数据，不放大型二进制内容。
Harness 会话存储Harness 自己管理的会话与运行资源。与项目状态分开；不把 Harness 会话当作已确认大纲或模板映射的权威来源。

3. 设计约束

  • 清单是逻辑视图：实现时可以合并为少量内存仓储和图状态，避免为每一行提前引入独立基础设施。
  • 以项目 ID、任务 ID 和版本关联数据；确认后的大纲与模板映射作为生成任务输入快照。并发修改须检测版本冲突。
  • 模型、工具或子智能体的输出先由后端校验，再进入项目状态；人工确认是显式状态变更。
  • 第一阶段文件可能留在磁盘，但对应项目索引和会话存在内存中，进程重启不保证重新发现或恢复。
  • 后续引入数据库和持久化检查点时，再定义表结构、迁移、保留期限和恢复策略；不把当前字段草案当作已冻结数据库设计。

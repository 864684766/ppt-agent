任务 03：模型流式对话（2026-11-02）

POST /ppt-agent/v1/chat 接收 {"message":"你好"}，返回 text/event-stream（UTF-8）。保留用户修改的 /ppt-agent/v1 前缀。请求不变，响应从单个 JSON 改为 SSE；不兼容旧 reply 字段。

Postman → FastAPI 校验及依赖注入 → LangChainChatClient.stream_reply
        → ChatOpenAI.astream → 模型代理流 → delta 事件 → done 或 error

每个 delta 的 JSON 数据包含 text，客户端顺序拼接。块大小由模型与网络决定，不保证一块一个 token；不是逐字节切割。不对块 strip，保留 Markdown 空白。正常结束发 done（finish_reason=completed，仅表示流结束，不保证内容未被额度截断）；已知调用错误发 error（code、message）且不发 done。HTTP 响应开始后仍为 200，客户端不能只依赖状态码。未知错误或取消可能直接断流，没有终止事件应视为不完整。

参数校验失败返回 422；配置缺失或无效返回 503。LangChain astream 以异步生成器逐段产生正文，SSE 由 HTTP 层编码。两个生成器通过 aclosing 确保异常或取消时关闭上游，默认请求作用域 yield 依赖在流结束后释放 httpx 连接。尚无心跳、续传、持久化取消或对话历史。

配置 LLM_TIMEOUT_SECONDS 默认 60 秒（>0 且 ≤600），用于上游请求读等待，不是整个流总时限；LLM_MAX_TOKENS 默认 1024（1–32768，仍受模型约束）。无自动重试。httpx 0.28.1 为运行依赖，其他版本和锁文件未升级。LangSmith .env 接线、Harness 和任务专用模型业务调用未实现。

2026-11-02 实际启动 Uvicorn 并调用本机模型：收到 28 个 delta 和 done，首段约 6.43 秒、结束约 7.69 秒。临时脚本验证空白保留、错误分支与提前关闭清理。未实际操作 Postman，未专项验证网络断开和代理缓冲场景，验证进程已停止。

按用户要求不保留本步骤自动测试文件，采用 Postman / 断点及临时验证。请求、事件样例与限制见 接口调试说明。本步骤不新增业务 Store。

业务与系统解耦、局部移植（2026-11-02）

依赖契约与具体实现分离：domain/chat.py 仅使用标准库，定义 ChatClient 和 ModelCallError；路由只依赖契约。integrations/llm.py 实现契约并转换 SDK 异常，不导入 Settings、FastAPI 或项目路径。api/dependencies.py 是当前 HTTP 入口的组装边界，将 Settings 转换为基础地址、SecretStr 密钥、模型名、超时、输出上限及 HTTP 客户端参数。

api/routes/chat → domain/chat（契约）
api/dependencies → Settings + integrations/llm（组装）
integrations/llm → domain/chat + LangChain/OpenAI/httpx/Pydantic
api/streaming → 标准库 json
外部脚本 → 显式参数 + integrations/llm，无需 FastAPI 或 .env

复用范围：仅使用契约可移植 domain/chat.py（及包标记文件），无需第三方依赖；复用 LangChain 适配器需同时携带契约及相应 SDK 依赖，调用方负责关闭传入的 httpx 客户端；复用 SSE 编码只需 api/streaming.py。HTTP 请求校验与事件映射属于 API 层，不把 FastAPI 或 SSE 字符串传入业务层。后续 PPT 业务同样通过显式输入输出和薄工具适配器接入，不提前引入无职责的服务层。

检查结果：main 只组装应用和启动，Settings 负责读取配置，schemas 负责 HTTP 契约，SSE 编码不依赖模型；这些职责边界保留。规则已写入 AGENTS.md。验证：独立进程 python -S 成功导入对话契约；显式参数工厂通过模拟代理流验证；HTTP 健康、delta/done、error、输入校验和清理通过。未调用真实模型，未新增测试文件，不涉及依赖、环境变量或业务 Store 变化。

单一职责与结构化 SSE（2026-11-02）

encode_event 的输入扩展为 Mapping[str, JsonValue]，JsonValue 是递归 JSON 类型，支持嵌套对象、数组、数字、布尔值和 null。只编码调用方选定的公开字段；拒绝包含 CR/LF/空字符的事件名及 NaN/Infinity，不用 default=str 自动泄露对象。中文字符保留，UTF-8 编码由 StreamingResponse 完成。

tool_start、tool_result、progress、reasoning_summary 仅为未来事件示例，当前 /ppt-agent/v1/chat 仍仅产出 delta/done/error。文本流契约当前不携带工具事件或推理字段；后续应先定义独立的结构化运行事件契约，由 Agent/工作流产生，再由 API 转 SSE，不能由通用编码器识别 SDK 对象。推理摘要需显式产出，供应商公开 reasoning 字段的支持以 SDK、模型和代理实测为准，不保证获得完整内部思维链。前端须按事件名分别显示或聚合；Postman 可查看事件，不自动生成工具卡片。

单一职责检查：main 为应用组装/启动；router 为路由组装；routes/chat 为对话 HTTP 与流事件映射；schemas 为接口数据校验；dependencies 为 HTTP 入口的依赖组装/生命周期；streaming 为通用 SSE 编码；domain/chat 为独立契约；integrations/llm 为 LangChain 适配；settings 为配置读取/模型选择。各文件内的辅助函数服务同一职责，目前不需要继续机械拆分。未来大纲、模板业务规则不得进入路由或编码模块。单一职责原则及三层能力区别已加入 AGENTS.md。

验证：临时脚本对工具嵌套数据、摘要换行、进度做 JSON 往返；对非法事件名、非标准数值、不可编码对象检查拒绝；现有 HTTP delta/done 与健康检查通过。未新增测试文件、未调用真实模型、未验证前端工具展示。无依赖、配置或业务 Store 变更。

2. 运行流程与状态

创建项目导入资料 / 模板 / 技能研究与生成大纲编辑与确认识别与确认模板生成 / 渲染 / 检查下载或修改
CREATED → RESEARCHING → OUTLINE_DRAFT ↔ OUTLINE_EDITING
                                      ↓ 用户确认
                           TEMPLATE_ANALYZING
                                      ↓
                    WAITING_FOR_USER ↔ TEMPLATE_READY
                                      ↓
                        GENERATING → CHECKING → COMPLETED
                                      ↓
                           REVISING → 新的生成版本
任意可取消阶段 → CANCELLING → CANCELLED；错误 → FAILED（可重试）

上图是产品状态示意，WAITING_FOR_USER 可由资料不足、模板歧义或修改需求不明确等节点进入；答案恢复对应节点。任务状态与项目状态分开存储。生成只读取已确认的大纲和模板映射快照；每次修改产生新版本，写入采用乐观版本控制。

人工介入

第一阶段人工问题在当前进程内等待并恢复；进程重启后需重新发起。持久化检查点后续引入。Harness 的短时提问回调可桥接到前端，但跨重启恢复能力须实测。长时间等待优先由子任务返回结构化问题，结束子任务后保存问题并根据答案继续；跨重启持久化属于后续阶段；不得假设 SDK 回调在重启后自动恢复。

3. 子智能体与模型

子智能体输入与工具输出
LangChain 模板识别模板文件、结构解析、占位符、文本及页面缩略图；可调用视觉模型（仅在确认支持图片输入时）。候选角色、版式／样例页与槽位映射、依据、缺失项、需用户回答的问题。
Harness 模板使用确认的大纲、来源、模板映射、技能快照与被授权的 Python 工具。生成产物、预览、检查结果、错误或需用户决策的问题。不能修改业务权威状态。

子任务采用结构化协议：task_id、输入快照版本、可用技能／工具、超时与预算；结果包含状态、产物引用、证据、问题及错误。后端校验结果后才写入项目状态。视觉模型不可用时，退回结构与文本分析加人工确认。

模型路由

按任务配置模型、上下文限制、图片能力、预算及重试策略。候选包括用户现有的 GLM、DeepSeek、Kimi 系列，但具体模型能力、代理名称和价格不在本文臆测。使用任务样本比较内容质量、来源准确性、速度和费用后再确定默认值。百舸基础调用能力已由用户确认，不作为原型验证项；Harness 对该代理的 provider 配置仍需验证。

4. 模板识别和使用

识别结合 Open XML、母版／占位符、页面对象几何、文本语义和可用时的视觉模型。区分母版版式与实际样例页，记录证据而非依赖页面索引。目录或来源等业务角色通常没有可靠的通用标签。

模板上传 → 类型和安全检查 → 解析母版、版式、占位符、样例页
        → 渲染缩略图 → LangChain 子智能体提出角色与槽位
        → 缺失 / 歧义 → 用户选择或自由输入
        → 保存经确认的模板映射 → Harness 子智能体使用

映射记录模板文件哈希、版本、版式／页面标识、角色、标题与内容槽位、用户确认状态、兼容性警告及识别依据。模板变化时重新检查。缺少页面时允许用户补充文件、复用版式、AI 补全或省略可选角色；补全须预览确认。

内置模板来自逐项确认许可及兼容性的候选资源；PPT Master 是候选来源，不承诺资源均为可直接使用的 PPTX。检查字体、图标、图片及品牌使用条件，保存来源与许可证记录。首版不做在线模板搜索。

5. 技能与工具

支持标准技能目录：SKILL.md、可选 scripts/、references/、assets/。技能注册表保存元数据、版本、哈希、依赖和兼容性；更新对新任务生效，运行中任务锁定快照。技能可引用并执行脚本，运行记录关联任务与版本。兼容通用格式不代表所有 ClawHub／OpenClaw 专属工具可直接运行。

脚本在受控工作目录中运行，提供明确的文件与网络权限、时间／资源限制和依赖说明；记录执行命令及结果，并支持取消。导入时展示来源、脚本与所需权限。技能文本和外部资料视为数据，不自动授予新工具权限。

工具用途
搜索与网页提取可替换搜索服务；抓取正文、标题、URL 和访问时间，限制网络目标、大小及超时。
文件解析与引用解析 PDF、DOCX、TXT、Markdown，保存片段、文件名与可获得页码；OCR 后续增强。
模板分析与渲染解析结构、槽位、主题、文本；输出缩略图及兼容性报告。
PPTX 与质检写入原生对象，渲染预览，检查页数、可打开性、空内容、越界与字体问题。
技能执行发现技能、加载指令和资源、运行脚本、捕获日志及产物。

PPT Master：包含技能、Python 脚本、模板和制作流程，使用项目约定的 SVG 中间表示及转换工具链。原型评估 Harness 加载该技能、Windows 依赖、模板使用和输出质量；是否复用全部流程或局部脚本，待结果决定。

6. API 与数据设计

结构化数据、Graph State、Checkpointer、LangGraph Store 与文件存储的职责和阶段安排见 Store 与结构化状态清单。第一阶段不要求数据库或跨重启恢复。

以下为建议接口，具体请求和响应模式在实现时通过 OpenAPI 固化。所有写操作均需项目隔离；修改大纲和映射时携带版本号，冲突返回明确错误。

接口用途
POST /projects · GET /projects/{id}创建、查看项目与当前状态。
POST /projects/{id}/files上传资料或模板，返回文件标识及解析状态。
POST /projects/{id}/messages提交用户消息，触发大纲或修改工作流。
GET/PATCH /projects/{id}/outline · POST .../outline/confirm获取、编辑和确认大纲快照。
POST /templates/{id}/analyze · PUT /templates/{id}/mapping分析模板，保存用户确认的角色及槽位映射。
POST /skills · POST /skills/{id}/activate导入、检查并启用技能版本；项目显式绑定技能。
POST /projects/{id}/generations基于确认的快照启动生成或修订。
GET /tasks/{id} · GET /tasks/{id}/events · POST /tasks/{id}/cancel查询、SSE 事件和取消；事件支持重连及顺序标识。
POST /questions/{id}/answers · GET /artifacts/{id}提交人工答案；查看或下载生成文件和预览。

核心实体：Project、Conversation/Message、Source/SourceFragment、OutlineVersion/Item、Template/TemplateMapping、Skill/SkillVersion、Task/TaskEvent、UserQuestion/Answer、GenerationVersion/Artifact。引用外键和文件哈希，避免把二进制文件直接嵌入状态；模型密钥不进入业务状态或日志。

7. 运行、质量与原型

配置与运行

使用环境变量或本地未提交的配置管理模型地址、模型名称、密钥、存储路径及追踪开关；示例配置不包含密钥。之前聊天中暴露的密钥应在对应平台轮换。上传文件、生成结果和日志按项目分离；LangSmith 默认关闭或经明确配置启用，注意资料可能被发送至外部服务。

验证与验收

  1. 原型验证 Harness 的百舸 provider、Python SDK 调用、取消、错误、提问桥接、技能发现和脚本运行；记录无法保证的跨重启行为。
  2. 检验模板样本：标准母版、多母版、普通样例页、图片背景及特殊字体；分别记录识别、生成、渲染和许可。
  3. 评估 PPT Master 技能及依赖，验证能否与项目协议、确认流程和 Python 运行环境对接。
  4. 单元测试版本冲突、映射、来源和状态；集成测试 API、持久化恢复、取消与任务结果；端到端验证 8–12 页、打开、可编辑、预览及修订版本。
  5. 对渲染结果检查溢出和遮挡；视觉质量不能只靠程序断言，提供可供人工查看的页面预览。
关键风险：Harness 为快速演进的独立运行时；第三方技能依赖和脚本能力各异；复杂模板不可保证无损；渲染依赖字体与 Office 环境；视觉模型可用性及模型成本尚未确认。以上均通过可替换适配层、原型和兼容性报告处理。

插入任务：第一个 Agent 工具 list_materials（2026-11-02）

按工具清单中的开发顺序，先实现资料目录工具，而非技能发现工具。models/materials/material_source.py 和 domain/materials/material_catalog.py 定义不可变 MaterialSummary、MaterialPage 和纯函数 list_project_materials；tools/materials/list_materials_tool.py 使用 LangChain @tool 和 Pydantic 参数模型，将其暴露为模型可选择的 list_materials。外层 create_list_materials_tool 绑定 project_id 与目录快照；模型只能提供 origin、name_contains、offset、limit，不得切换项目。工具只列业务参考资料，不包括模板、技能和未关联历史文件。

功能分组、输入输出导航与依赖方向（2026-11-02）

目录公共校验由domain/materials/material_validator.py中的validate_material_catalog负责，只检查项目编号与项目内source_id唯一性。list_project_materials先调用它，再执行筛选、排序和分页；共享的validate_material_content_data调用它，再检查正文关联、版本和块编号；检索与读取各自引用共享校验。正文校验不再借用目录查询触发异常，不执行无关排序或构造目录页。该函数是内部业务能力，不是新增Agent工具；独立的共享模块只依赖资料实体，目录查询和正文检索分别引用它，彼此不依赖对方的操作模块。

models统一管理类型，内部按materials、chat、health功能分组。同一个工具的Input/Output与公开条目在同一个<操作>_contract.py中，查看传参与结果无需跨文件。资料来源与正文块分别定义，内部目录页和检索结果集中在material_query_results.py；该模块不导入Pydantic或Agent框架，供业务查询独立使用。按职责、依赖和实际复用需求拆分，不按类数量机械拆文件。类型导航统一见models/README.md，包含定义位置、创建方和使用方；不依赖到多个按技术角色分类的文件夹中猜测。

已确认待实现：真实上传资料如何进入目录（2026-11-02）

真实运行使用与测试相同的MaterialSummary类型，但字段值来自上传和解析的实际结果。样本只是手动构造，正式数据由登记模块构造；不是把文件转成“测试数据”。当前只实现了接收目录快照的工具，以下上传、登记及内存目录仍待开发。

  1. 用户按“业务资料”用途上传文件；后端确定所属项目、分配source_id、保存原文件到本地磁盘。
  2. 读取实际名称和格式等元数据，构造MaterialSummary并加入当前项目的进程内存资料目录。先标记pending，未知page_count为None；project_id不由模型选择。
  3. 解析文本，扫描件需要时使用本机OCR。成功后创建新的不可变摘要替换目录记录，标记ready并填入可获得页数；失败标记failed。文件上传成功不等于正文解析成功。
  4. 正文和原页/文本块定位按source_id及版本单独关联保存，MaterialSummary只保留目录摘要，不包含正文或本机路径。
  5. 宿主取得当前项目目录快照，传给create_list_materials_tool。工具查询后只返回允许公开的字段。
  6. 目录新增或解析状态更新后，宿主需重建工具供后续调用使用。旧工具不会自动看到新增记录；同一轮分页保持同一快照，避免位置漂移。

模板、技能和未关联历史文件不混入业务资料目录。第一阶段结构化目录保存在内存，原文件保存在磁盘；不要求先建数据库，也不承诺进程重启后恢复目录。后续网页正文抓取成功并登记时也构造相同资料摘要，origin为web并保留原URL。

第二个工具：search_materials（2026-11-02）

工具已独立实现，资料摘要与正文片段由宿主提供并复制快照；模型只传queries、source_ids、origin、max_results、max_chars_per_match。来源范围和原文不由模型指定。资料关系在纯业务层校验：片段须关联当前项目ready来源、版本一致、同来源版本块ID唯一；指定不存在/未ready或正文未载入的来源明确报错。

任务 03：模型流式对话（2026-11-02）

POST /ppt-agent/v1/chat 接收 {"message":"你好"}，返回 text/event-stream（UTF-8）。保留用户修改的 /ppt-agent/v1 前缀。请求不变，响应从单个 JSON 改为 SSE；不兼容旧 reply 字段。

Postman → FastAPI 校验及依赖注入 → LangChainChatClient.stream_reply
        → ChatOpenAI.astream → 模型代理流 → delta 事件 → done 或 error

每个 delta 的 JSON 数据包含 text，客户端顺序拼接。块大小由模型与网络决定，不保证一块一个 token；不是逐字节切割。不对块 strip，保留 Markdown 空白。正常结束发 done（finish_reason=completed，仅表示流结束，不保证内容未被额度截断）；已知调用错误发 error（code、message）且不发 done。HTTP 响应开始后仍为 200，客户端不能只依赖状态码。未知错误或取消可能直接断流，没有终止事件应视为不完整。

参数校验失败返回 422；配置缺失或无效返回 503。LangChain astream 以异步生成器逐段产生正文，SSE 由 HTTP 层编码。两个生成器通过 aclosing 确保异常或取消时关闭上游，默认请求作用域 yield 依赖在流结束后释放 httpx 连接。尚无心跳、续传、持久化取消或对话历史。

配置 LLM_TIMEOUT_SECONDS 默认 60 秒（>0 且 ≤600），用于上游请求读等待，不是整个流总时限；LLM_MAX_TOKENS 默认 1024（1–32768，仍受模型约束）。无自动重试。httpx 0.28.1 为运行依赖，其他版本和锁文件未升级。LangSmith .env 接线、Harness 和任务专用模型业务调用未实现。

POST /projects · GET /projects/{id}创建、查看项目与当前状态。
POST /projects/{id}/files上传资料或模板，返回文件标识及解析状态。
POST /projects/{id}/messages提交用户消息，触发大纲或修改工作流。
GET/PATCH /projects/{id}/outline · POST .../outline/confirm获取、编辑和确认大纲快照。
POST /templates/{id}/analyze · PUT /templates/{id}/mapping分析模板，保存用户确认的角色及槽位映射。
POST /skills · POST /skills/{id}/activate导入、检查并启用技能版本；项目显式绑定技能。
POST /projects/{id}/generations基于确认的快照启动生成或修订。
GET /tasks/{id} · GET /tasks/{id}/events · POST /tasks/{id}/cancel查询、SSE 事件和取消；事件支持重连及顺序标识。
POST /questions/{id}/answers · GET /artifacts/{id}提交人工答案；查看或下载生成文件和预览。

核心实体：Project、Conversation/Message、Source/SourceFragment、OutlineVersion/Item、Template/TemplateMapping、Skill/SkillVersion、Task/TaskEvent、UserQuestion/Answer、GenerationVersion/Artifact。引用外键和文件哈希，避免把二进制文件直接嵌入状态；模型密钥不进入业务状态或日志。

7. 运行、质量与原型

配置与运行

使用环境变量或本地未提交的配置管理模型地址、模型名称、密钥、存储路径及追踪开关；示例配置不包含密钥。之前聊天中暴露的密钥应在对应平台轮换。上传文件、生成结果和日志按项目分离；LangSmith 默认关闭或经明确配置启用，注意资料可能被发送至外部服务。

验证与验收

  1. 原型验证 Harness 的百舸 provider、Python SDK 调用、取消、错误、提问桥接、技能发现和脚本运行；记录无法保证的跨重启行为。
  2. 检验模板样本：标准母版、多母版、普通样例页、图片背景及特殊字体；分别记录识别、生成、渲染和许可。
  3. 评估 PPT Master 技能及依赖，验证能否与项目协议、确认流程和 Python 运行环境对接。
  4. 单元测试版本冲突、映射、来源和状态；集成测试 API、持久化恢复、取消与任务结果；端到端验证 8–12 页、打开、可编辑、预览及修订版本。
  5. 对渲染结果检查溢出和遮挡；视觉质量不能只靠程序断言，提供可供人工查看的页面预览。
关键风险：Harness 为快速演进的独立运行时；第三方技能依赖和脚本能力各异；复杂模板不可保证无损；渲染依赖字体与 Office 环境；视觉模型可用性及模型成本尚未确认。以上均通过可替换适配层、原型和兼容性报告处理。

识别结果先返回 LangGraph 状态，经过校验及必要的用户确认，再由 LangGraph 调用 Harness 传入确认结果。LangGraph 是业务状态的权威来源；Harness 保留子任务会话，但不能独立改变已确认的大纲或模板映射。LangChain 与 Harness 分别管理模型调用，使用同一代理不代表共享模型对象。Harness SDK 通过子进程 JSON-RPC 控制独立运行时；直接控制 LangChain 模型对象不是文档确认的开箱能力。

组件选择及职责
API / 运行Python、FastAPI、Pydantic；SSE 推送进度，后台任务执行器独立于请求生命周期。
智能体LangGraph 编排；LangChain 识别模板；Harness Python SDK 驱动模板使用子智能体。固定版本并通过适配层隔离。
PPTXpython-pptx 为首选候选；必要时读取 Open XML。复杂样例页复制、.potx 和母版继承以实测为准。
渲染渲染将 PPTX 转成 PDF 或页面图片供预览检查，不负责生成 PPTX。Harness SDK 提供可选 Office 本地 API，文档示例是 DOCX，PPTX 渲染支持和 Windows 效果需实测；也可评估 LibreOffice。
存储 / 追踪第一阶段采用本地文件和内存状态，重启后不保证恢复任务；数据库与持久化检查点后续引入。LangSmith 可配置启用及脱敏。

人工介入

第一阶段人工问题在当前进程内等待并恢复；进程重启后需重新发起。持久化检查点后续引入。Harness 的短时提问回调可桥接到前端，但跨重启恢复能力须实测。长时间等待优先由子任务返回结构化问题，结束子任务后保存问题并根据答案继续；跨重启持久化属于后续阶段；不得假设 SDK 回调在重启后自动恢复。

3. 子智能体与模型

子智能体输入与工具输出
LangChain 模板识别模板文件、结构解析、占位符、文本及页面缩略图；可调用视觉模型（仅在确认支持图片输入时）。候选角色、版式／样例页与槽位映射、依据、缺失项、需用户回答的问题。
Harness 模板使用确认的大纲、来源、模板映射、技能快照与被授权的 Python 工具。生成产物、预览、检查结果、错误或需用户决策的问题。不能修改业务权威状态。

子任务采用结构化协议：task_id、输入快照版本、可用技能／工具、超时与预算；结果包含状态、产物引用、证据、问题及错误。后端校验结果后才写入项目状态。视觉模型不可用时，退回结构与文本分析加人工确认。

模型路由

按任务配置模型、上下文限制、图片能力、预算及重试策略。候选包括用户现有的 GLM、DeepSeek、Kimi 系列，但具体模型能力、代理名称和价格不在本文臆测。使用任务样本比较内容质量、来源准确性、速度和费用后再确定默认值。百舸基础调用能力已由用户确认，不作为原型验证项；Harness 对该代理的 provider 配置仍需验证。

4. 模板识别和使用

识别结合 Open XML、母版／占位符、页面对象几何、文本语义和可用时的视觉模型。区分母版版式与实际样例页，记录证据而非依赖页面索引。目录或来源等业务角色通常没有可靠的通用标签。

模板上传 → 类型和安全检查 → 解析母版、版式、占位符、样例页
        → 渲染缩略图 → LangChain 子智能体提出角色与槽位
        → 缺失 / 歧义 → 用户选择或自由输入
        → 保存经确认的模板映射 → Harness 子智能体使用

映射记录模板文件哈希、版本、版式／页面标识、角色、标题与内容槽位、用户确认状态、兼容性警告及识别依据。模板变化时重新检查。缺少页面时允许用户补充文件、复用版式、AI 补全或省略可选角色；补全须预览确认。

内置模板来自逐项确认许可及兼容性的候选资源；PPT Master 是候选来源，不承诺资源均为可直接使用的 PPTX。检查字体、图标、图片及品牌使用条件，保存来源与许可证记录。首版不做在线模板搜索。

5. 技能与工具

支持标准技能目录：SKILL.md、可选 scripts/、references/、assets/。技能注册表保存元数据、版本、哈希、依赖和兼容性；更新对新任务生效，运行中任务锁定快照。技能可引用并执行脚本，运行记录关联任务与版本。兼容通用格式不代表所有 ClawHub／OpenClaw 专属工具可直接运行。

脚本在受控工作目录中运行，提供明确的文件与网络权限、时间／资源限制和依赖说明；记录执行命令及结果，并支持取消。导入时展示来源、脚本与所需权限。技能文本和外部资料视为数据，不自动授予新工具权限。

工具用途
搜索与网页提取可替换搜索服务；抓取正文、标题、URL 和访问时间，限制网络目标、大小及超时。
文件解析与引用解析 PDF、DOCX、TXT、Markdown，保存片段、文件名与可获得页码；OCR 后续增强。
模板分析与渲染解析结构、槽位、主题、文本；输出缩略图及兼容性报告。
PPTX 与质检写入原生对象，渲染预览，检查页数、可打开性、空内容、越界与字体问题。
技能执行发现技能、加载指令和资源、运行脚本、捕获日志及产物。

PPT Master：包含技能、Python 脚本、模板和制作流程，使用项目约定的 SVG 中间表示及转换工具链。原型评估 Harness 加载该技能、Windows 依赖、模板使用和输出质量；是否复用全部流程或局部脚本，待结果决定。

6. API 与数据设计

结构化数据、Graph State、Checkpointer、LangGraph Store 与文件存储的职责和阶段安排见 Store 与结构化状态清单。第一阶段不要求数据库或跨重启恢复。

以下为建议接口，具体请求和响应模式在实现时通过 OpenAPI 固化。所有写操作均需项目隔离；修改大纲和映射时携带版本号，冲突返回明确错误。

接口用途
POST /projects · GET /projects/{id}创建、查看项目与当前状态。
POST /projects/{id}/files上传资料或模板，返回文件标识及解析状态。
POST /projects/{id}/messages提交用户消息，触发大纲或修改工作流。
GET/PATCH /projects/{id}/outline · POST .../outline/confirm获取、编辑和确认大纲快照。
POST /templates/{id}/analyze · PUT /templates/{id}/mapping分析模板，保存用户确认的角色及槽位映射。
POST /skills · POST /skills/{id}/activate导入、检查并启用技能版本；项目显式绑定技能。
POST /projects/{id}/generations基于确认的快照启动生成或修订。
GET /tasks/{id} · GET /tasks/{id}/events · POST /tasks/{id}/cancel查询、SSE 事件和取消；事件支持重连及顺序标识。
POST /questions/{id}/answers · GET /artifacts/{id}提交人工答案；查看或下载生成文件和预览。

核心实体：Project、Conversation/Message、Source/SourceFragment、OutlineVersion/Item、Template/TemplateMapping、Skill/SkillVersion、Task/TaskEvent、UserQuestion/Answer、GenerationVersion/Artifact。引用外键和文件哈希，避免把二进制文件直接嵌入状态；模型密钥不进入业务状态或日志。

7. 运行、质量与原型

配置与运行

使用环境变量或本地未提交的配置管理模型地址、模型名称、密钥、存储路径及追踪开关；示例配置不包含密钥。之前聊天中暴露的密钥应在对应平台轮换。上传文件、生成结果和日志按项目分离；LangSmith 默认关闭或经明确配置启用，注意资料可能被发送至外部服务。

验证与验收

  1. 原型验证 Harness 的百舸 provider、Python SDK 调用、取消、错误、提问桥接、技能发现和脚本运行；记录无法保证的跨重启行为。
  2. 检验模板样本：标准母版、多母版、普通样例页、图片背景及特殊字体；分别记录识别、生成、渲染和许可。
  3. 评估 PPT Master 技能及依赖，验证能否与项目协议、确认流程和 Python 运行环境对接。
  4. 单元测试版本冲突、映射、来源和状态；集成测试 API、持久化恢复、取消与任务结果；端到端验证 8–12 页、打开、可编辑、预览及修订版本。
  5. 对渲染结果检查溢出和遮挡；视觉质量不能只靠程序断言，提供可供人工查看的页面预览。
关键风险：Harness 为快速演进的独立运行时；第三方技能依赖和脚本能力各异；复杂模板不可保证无损；渲染依赖字体与 Office 环境；视觉模型可用性及模型成本尚未确认。以上均通过可替换适配层、原型和兼容性报告处理。

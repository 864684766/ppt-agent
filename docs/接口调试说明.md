# FastAPI 基础服务调试

在项目根目录 `E:\test\ppt-agent` 执行：

```powershell
uv run --locked python main.py
```

Uvicorn 是运行 HTTP 服务的服务器。此命令不会调用模型，也不是运行单元测试。按 Ctrl+C 停止服务。
直接运行 main.py 会进入启动分支，从 APP_HOST、APP_PORT 读取监听配置；默认 127.0.0.1:8000。导入 main 模块不会启动监听。可将 .env.example 复制为项目根目录的 .env 修改配置，已有 .env 时自行合并，不覆盖。系统环境变量优先于 .env。

## PyCharm 断点调试

可以直接在 main.py 上使用 Debug，解释器选择项目虚拟环境，工作目录为项目根目录。
也可以创建 Python 运行配置，选择 Module name（模块名称）：

| 配置项 | 值 |
| --- | --- |
| 模块名称 | `uvicorn` |
| 参数 | `main:app --host 127.0.0.1 --port 8000` |
| Python 解释器 | `E:\test\ppt-agent\.venv\Scripts\python.exe` |
| 工作目录 | `E:\test\ppt-agent` |

点击 Debug 启动，在 `api/health.py` 的 `return HealthResponse()` 行设置断点，再从 Postman 发送请求。程序暂停时可查看变量、单步执行或继续运行。调试时先不加 `--reload`，避免重载产生的额外进程影响断点。

## Postman 手工验证

本阶段请求均不需要认证或请求体。

| 方法与地址 | 预期 |
| --- | --- |
| `GET http://127.0.0.1:8000/health` | HTTP 200，JSON 为 `{"status":"ok"}` |
| `GET http://127.0.0.1:8000/openapi.json` | HTTP 200，包含 `/health` 的接口定义 |
| `GET http://127.0.0.1:8000/not-found` | HTTP 404，默认 JSON 为 `{"detail":"Not Found"}` |
| `POST http://127.0.0.1:8000/health` | HTTP 405，默认 JSON 为 `{"detail":"Method Not Allowed"}` |

浏览器打开 `http://127.0.0.1:8000/docs` 查看交互式接口文档；该页面的静态资源需要浏览器访问外部 CDN，如果界面未加载，可先用 Postman 访问 `/openapi.json` 确认接口定义。

404 和 405 使用 FastAPI 默认错误响应；后续出现业务错误时再设计对应的处理方式。健康检查只说明 HTTP 服务存活，不检查模型、Harness 或 PPTX 生成能力。

## 发布时启动

部署时由进程管理器或容器执行启动命令，并负责持续运行与失败重启。例如在 PowerShell 中使用环境变量监听所有网络接口：

```powershell
$env:APP_HOST = "0.0.0.0"
$env:APP_PORT = "8000"
uv run --locked python main.py
```

0.0.0.0 是监听地址，客户端应访问服务器实际 IP 或域名；访问范围还取决于防火墙和部署网络。正式运行不启用 --reload。
当前设计使用进程内状态，先保持单 worker；多个 worker 的内存互不共享，需在后续引入共享状态与任务机制后再评估扩展。

注意：APP_HOST、APP_PORT 是本项目启动入口读取的配置。直接执行 uvicorn main:app 时不会自动读取这两个变量，需使用 Uvicorn 自己的参数或配置；本项目推荐运行 main.py 统一读取。

## 按任务配置模型

| 环境变量 | 用途 |
| --- | --- |
| LLM_BASE_URL / LLM_API_KEY | 当前几个任务共享的模型代理地址与密钥 |
| LLM_MODEL | 默认模型 |
| LLM_OUTLINE_MODEL | 大纲生成与对话编辑 |
| LLM_TEMPLATE_ANALYSIS_MODEL | LangChain 模板识别子智能体 |
| LLM_PPT_GENERATION_MODEL | Harness 模板使用与 PPT 生成子智能体 |

任务专用名称优先，留空时退回 LLM_MODEL；两者都为空时，仅在请求该任务模型时报告配置缺失，不阻止健康检查服务启动。当前只实现配置读取与选择，实际模型客户端和 Harness 路由将在对应开发任务中接入。指定名称不会自动赋予模型视觉能力，需按代理实际支持能力选择。

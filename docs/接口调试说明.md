# FastAPI 基础服务调试

在项目根目录 `E:\test\ppt-agent` 执行：

```powershell
uv run --locked python main.py
```

Uvicorn 是运行 HTTP 服务的服务器。启动本身不会调用模型；请求 POST /ppt-agent/v1/chat 才会调用模型。此命令不是运行单元测试。按 Ctrl+C 停止服务。
直接运行 main.py 会进入启动分支，从 APP_HOST、APP_PORT 读取监听配置；默认 127.0.0.1:8000。导入 main 模块不会启动监听。可将 .env.example 复制为项目根目录的 .env 修改配置，已有 .env 时自行合并，不覆盖。系统环境变量优先于 .env。

## 发布时启动

部署时由进程管理器或容器执行启动命令，并负责持续运行与失败重启。例如在 PowerShell 中使用环境变量监听所有网络接口：

```powershell
$env:APP_HOST = "0.0.0.0"
$env:APP_PORT = "8000"
uv run --locked python main.py
```

0.0.0.0 是监听地址，客户端应访问服务器实际 IP 或域名；访问范围还取决于防火墙和部署网络。正式运行不启用 --reload。
当前设计使用进程内状态，先保持单 worker；多个 worker 的内存互不共享，需在后续引入共享状态与任务机制后再评估扩展。

注意：APP_HOST、APP_PORT 是本项目启动入口读取的配置。直接执行 uvicorn main:app 时不会自动读取这两个变量，需使用 Uvicorn 自己的参数或配置；本项目推荐运行 main.py 统一读取。

## 模型流式对话：Postman 与断点

用户已调整路由前缀，当前地址为 `POST http://127.0.0.1:8000/ppt-agent/v1/chat`，不再使用旧的 /debug/chat。

1. 本机 .env 填写 LLM_BASE_URL、LLM_API_KEY、LLM_MODEL；启动或 Debug main.py。
2. Postman 选择 POST，Body → raw → JSON；Content-Type: application/json。
3. 可增加请求头 Accept: text/event-stream。无需在 Postman 填写模型密钥。
4. 发送以下消息，在支持 SSE 的 Postman HTTP 客户端中观察事件逐条出现；UI 因版本可能不同。

```json
{"message":"请详细说明制作一份律师培训PPT的步骤。"}
```

响应 Content-Type 为 text/event-stream; charset=utf-8，不再返回单个 reply JSON：

```text
event: delta
data: {"text": "制作"}

event: delta
data: {"text": "律师培训PPT"}

event: done
data: {"finish_reason": "completed"}

```

delta.text 是新增正文，客户端按顺序拼接；每块可能包含多个 token，不能等同于一个字符或字节。保留空格和换行。JSON 的转义换行需要解析后展示。done 表示流正常完成，不保证模型没有因输出额度而截断内容。

流开始后 HTTP 已为 200，上游超时或服务错误通过事件通知，客户端必须同时检查事件：

```text
event: error
data: {"code": "model_timeout", "message": "模型响应超时，请稍后重试。"}

```

失败后没有 done；已收到文本可能只是部分回答。其他已知调用错误 code 为 model_error。未知程序错误、断网或取消可能直接断流；没有收到 done/error 应视为未完整结束。本阶段不支持断点续传、心跳或持久化任务。

参数错误仍返回普通 HTTP 422；配置缺失、格式或地址不合法返回 503。两者发生在开始发送 SSE 之前。LLM_TIMEOUT_SECONDS 默认 60，属于上游请求/读等待超时，不是整个流的总时间；LLM_MAX_TOKENS 默认 1024，仍限制整次输出额度，推理模型可能需要更高额度。

断点建议：api/routes/chat.py 的 return StreamingResponse → integrations/llm.py 的 async for chunk → api/routes/chat.py 的 yield encode_event。yield 每执行一次就交出一个事件。打断点会人为暂停流，可能触发客户端或上游超时。

若 Postman 没有逐条展示，先检查响应类型与客户端 SSE 支持，也可以用 PowerShell 的 curl.exe（-N 禁止客户端缓冲）交叉检查：

```powershell
'{"message":"请详细介绍制作PPT的步骤。"}' | Set-Content -Encoding utf8 request.json
curl.exe -N -X POST "http://127.0.0.1:8000/ppt-agent/v1/chat" -H "Content-Type: application/json" -H "Accept: text/event-stream" --data-binary "@request.json"
```

反向代理需要关闭缓冲；响应已设置 Cache-Control: no-cache 和 X-Accel-Buffering: no，但实际效果仍取决于代理配置。取消 Postman 请求将断开当前流，不是持久化任务取消接口。

LangSmith .env 配置尚未接线；外部系统环境的 SDK 追踪配置可能独立生效。

## 结构化 SSE 编码说明（2026-11-02）

api/streaming.py 的 encode_event 支持递归 JSON 数据，工具参数或结果无需强制转成字符串。事件名称不得为空或包含换行/空字符，数据不得包含 NaN/Infinity 或未转换的 SDK 对象。正文换行通过 JSON 转义，不会提前结束 SSE 事件。

未来格式示例（当前聊天接口尚不产出）：

```text
event: tool_start
data: {"call_id":"call-1","name":"analyze_template","arguments":{"pages":[1,2],"preview":true}}

event: tool_result
data: {"call_id":"call-1","result":{"roles":["cover","content"]},"error":null}

event: reasoning_summary
data: {"text":"正在比较模板版式，并整理需用户确认的项目。"}

```

当前仍仅有 delta/done/error；工具事件、模型公开推理片段和工作流摘要需要后续单独定义契约、接入产出及前端展示，不因为编码器支持就自动生效。不保证可获取模型完整内部思维链。前端可以用 call_id 配对工具开始与结果，但此 ID 尚未进入当前业务 Store。

1. 先看典型运行过程

下面是拟议运行场景，不是当前已接入的流程，也不是固定工具链。编号按常见首次使用位置排列；已知资料可直接读取，已知网页 URL 可直接抓取。资料研究可以循环，人工反馈可以随时插入。

A. 专业准备（需要时）
   list_skills → read_skill
                  ↓ 技能要求执行脚本时
                运行环境的执行工具 → 读取执行结果 → 按技能继续
                （可以再次 read_skill；不是读完就把所有脚本跑一遍）
                  ↓
B. 资料研究（本地、联网任选或结合）
   本地：用户上传业务文件 → 系统解析/OCR并登记       [用户/API/内部能力]
                                    ↓
                           模型按需选择 list_materials / search_materials / read_material
                                    ↑
   联网：search_web → fetch_webpage → 登记选中网页正文
                      ↓             （需要复查时共用上述三工具）
                    正文可直接用于当前分析，无须重复读取
                  ↓
   Agent 对话生成/修改大纲 → 用户确认               [推理与编排步骤]
                  ↓
C. 模板分析与人工反馈
   用户上传模板 / 选择内置模板                       [用户/API]
     → inspect_template → Agent 判断页角色
     → 缺页或歧义时通过后续人工反馈通道提问（工具形式未定）
     → 用户补传 / 指定角色 / 确认自动补齐
                  ↓

   build_presentation → check_presentation → 有问题则修订再检查
                  ↓
   下载 PPTX → Windows PowerPoint 手工打开验收       [交付与集成验证]

贯穿：ask_user 在任何需要用户决策的位置使用。
可选后续：render_pptx 生成页面图片，不是第一阶段必需步骤。

2. 先分清“资料”“模板”和“技能”

这里的“当前项目资料”，指本次 PPT 所属项目中已明确加入、用于内容取证和引用的资料集合。资料列表不是电脑目录，也不是账号全部历史文件。这里描述的是逻辑范围，不要求先引入数据库。

对象例子是否出现在 list_materials如何加入
上传的业务参考文件法律 PDF、员工手册 Word、销售报表、作为内容参考的旧 PPT是；返回解析状态与来源 ID用户按“业务资料”用途上传，系统登记
联网取得并纳入项目的正文选中的政府公告网页正文是；来源类型为 web，保留原 URL 和抓取时间Agent 抓取选中网页后，系统登记正文快照
搜索结果摘要和候选 URL搜索引擎返回的十条候选链接否；候选结果标识与已导入来源 ID 分开选中并成功抓取正文后才成为项目资料，不自动导入所有结果
PPT 设计模板只有三页的公司风格模板、完整内置模板否；使用 template_id 单独管理用户按“设计模板”用途上传或选择内置模板
其他项目 / 未关联的历史文件上周做另一份 PPT 上传的案例集否用户明确复用并加入当前项目后，才进入资料范围
技能说明及附属资源律师技能 SKILL.md、技能参考规范和脚本否；使用 skill_id 管理通过技能管理加载，SKILL.md由read_skill读取；附属资源入口待定

文件格式不决定用途。同一个 .pptx 若用来提取公司业务数据，是业务资料；若用来复用背景、母版和版式，是模板。需要两种用途时明确关联为两种对象，不由扩展名猜测。

4. 每个工具的输入、输出与边界

以下为语义级输入输出，参数名称和完整 JSON Schema 在逐项设计时确定。source_id 是来源标识，file_id 是文件标识，artifact_id 是产物标识；Agent 不需要持有任意本机绝对路径。项目范围由运行上下文绑定。

01 · list_skills — 发现本地技能 独立实现与真实目录验证完成

调用目的
发现项目内置skills/有哪些技能及其用途，不保证它们已适配运行。
输入
keyword可选，默认空，最多200字符；编号、名称、用途的字面子串筛选，不自动翻译，无分页。
输出
items：skill_id为一级目录编号、name为声明名称、description为用途说明、version为顶层或metadata声明版本（缺失null）；returned_count为本次条数。
使用方
内容与制作Agent按需使用，当前尚未接模型循环。
职责边界
固定读取项目根目录skills/，无目录环境变量；每次实际调用重新扫描，只读64KiB内的YAML头部。不合读取格式的技能记录WARNING日志后忽略，根目录不可用报错。不读全文、不执行代码、不安装、不联网；完整说明由read_skill读取。不检查技能依赖、不分析脚本或执行步骤、不判断运行可用性；日志只针对介绍读取与格式问题，不返回给模型；服务启动及独立结果测试由宿主统一初始化日志；LOG_LEVEL选择级别，LOG_OUTPUT选择文件、控制台或两者，工具不自行管理处理器。
测试状态
JSON定义及用户实际目录验证2项通过：固定读取skills/，返回fitness-nutrition、flyai、legal-issue-research三项；chef-assistant读取介绍失败，按约定记录WARNING后跳过。见测试与断点说明。

05 · fetch_webpage — 读取网页 独立实现与真实搜索集成验证完成

调用目的
读取search_web选中URL的静态HTML文本。
输入
url必填，1–4096字符，HTTP/HTTPS地址，不是candidate_id；max_chars默认12000，100–50000字符。
输出
requested_url输入地址、final_url重定向后地址、title标题、text文本、returned_chars返回字符数、extracted_chars提取总字符数、truncated截断标记、fetched_at为UTC抓取时间，非发布日期。
职责边界
只读取一个URL，不执行JavaScript、不登录、不下载附件、不OCR；文本可能含页面杂项、登录或验证码提示。不会登记资料，不返回source_id，不能直接用read_material读取；资料登记后续接线。部分失败明确报错，不以搜索摘要代替正文。
测试状态
JSON检查与真实search_web候选抓取2项通过，无模拟数据；此次提取1857字符，但文章不切题，不代表相关性验证。详见网页工具调试说明。

B · 联网资料，异步调用ainvoke。

5. 技能脚本：不必另造 run_skill_script，但要有执行入口

接受不单独提供 run_skill_script 的设计。技能可以由 SKILL.md、参考资源和可执行脚本组成。read_skill 只负责读取；Agent 按技能说明决定下一步。技能含脚本，并不要求工具必须叫 run_skill_script，也不意味着读到文件就自动执行。

read_skill（SKILL.md）
   → 理解步骤；需要时通过实际提供的文件读取能力读取参考资源
   → 技能要求运行 scripts/analyze.py 时
      → 调用实际提供给 Agent 的命令执行工具
      → 读取退出状态、stdout/stderr、生成文件信息
   → 根据执行结果继续技能；需要时再读资源/执行下一步

建议优先复用运行时已有的执行工具。如果选用的 Harness 运行配置已有可调用的命令执行工具，就让该工具承担脚本运行，不重复添加同职责入口；具体名称与可用性在 Harness 接线时按实际 SDK 文档和配置核对，本文不把它写成已接入能力。LangChain 侧也必须显式提供执行工具或执行适配器，单纯读取 Markdown 不会自动获得执行能力。

如果两个子智能体都需要执行脚本，可在底层共用一个独立 Python 进程执行模块，分别由各运行时适配。它处理解释器、工作目录、参数、依赖缺失、超时、取消和执行结果；这是内部模块。模型可调用的命令入口则属于运行时工具，必须在实际工具清单中列明，不能把它隐藏成“模型自己就会 exec”。只有现有执行入口不能满足实际需求时，再讨论专门的脚本工具。

你说的“exec 一下”如果指运行命令，理解正确。Python 的 exec() 是在当前 Python 进程执行代码字符串；启动技能的 Python/其他脚本通常使用进程调用，例如 subprocess，二者不是同一个概念。执行应遵循技能要求的时机和参数，结果返回 Agent 后继续；不是 read_skill 在内部顺便执行脚本。

6. 用法示例

用户上传《劳动合同法.pdf》《员工手册.docx》《案例扫描件.pdf》，要求制作解除劳动合同培训 PPT。Agent 可以跨三份资料检索，但只读取命中的具体范围：

list_materials → search_materials（解除、辞退等相关词）→ read_material（具体来源和位置）→ 必要时换词再搜 → 根据原文生成带来源的大纲

“解除”和“终止”等相关词只能用于扩大查找范围，不代表概念等价。OCR 是扫描件读取过程中的内部步骤；本机 OCR 结果也应保留页序、警告等定位信息。

联网例子

没有上传文件，用户要求制作“某行业最新政策”PPT：

search_web（主题关键词；第一版无时间筛选）→ 选择官方网页 → fetch_webpage（正文与来源 ID）→ 直接分析正文；需要跨来源比较时，list_materials（web）→ search_materials（政策术语）→ read_material（对应段落）。

本地与联网混合时，例如对照上传的《公司制度.docx》和已抓取的政府公告，search_materials 可跨这两个来源检索，再逐一 read_material 核实。search_materials 不会重新访问互联网；它查的是已登记正文快照。需要更新网页时使用联网工具重新抓取并记录新版本。

本地上传的时间关系

上传时：用户/API 接收文件 → 内部解析/OCR并登记。上传后：Agent 可以 list_materials 查看目录；若运行上下文已经给出文件 ID 和状态，可跳过列表直接读。模板上传则进入 template_id 管理，不进入这个资料目录。

8. 工具、内部封装和其他步骤分别是什么？

第 3、4 节的 11 项都设计为 Agent 工具候选；运行时的脚本执行工具另行接线。下面这些条目是解释性对照，不是额外的工具；其中有内部方法，也有 API、基础设施、Agent 推理和用户操作，不能一概称为“系统封装方法”。

Agent 发出 read_material 调用                 [工具入口]
        ↓
参数校验、项目范围和长度限制                   [调用边界]
        ↓
资料服务定位内容                              [业务/应用方法]
        ↓
必要时调用 PDF 解析器或 Windows 本机 OCR        [内部适配器/方法]
        ↓
读取/缓存解析内容并返回来源定位                 [存储与内部方法]
        ↓
结构化工具结果交给 Agent                       [工具消息适配]
工具的定义与调用机制：本清单所说的工具，是向模型提供名称、描述和参数 Schema，让模型可以选择并提出调用请求的能力入口。模型输出工具名和参数，运行时校验后分派执行，再把工具结果交回模型。模型不直接执行 Python 代码。普通方法如果没有暴露给模型，就不是此处的 Agent 工具；但工具实现仍可以由单元测试或固定工作流直接调用，不要求只能由模型触发。
模型选择 search_materials 并输出参数       [模型决策]
    → 运行时校验/分派 → 工具入口 → 内部检索模块 [程序执行]
    → 带来源的工具结果 → 模型继续分析          [结果反馈]

工具通常是暴露给 Agent 的薄入口，下面可以调用多个内部方法。同一个内部方法也能被固定工作流直接调用。用户上传文件走 API，Agent 对大纲的推理是模型任务，用户确认是用户行为，它们不是都包装成工具。

内容本清单的处理方式
OCR、PDF/DOCX 解析、编码转换作为资料导入/读取的内部能力。OCR 明确要求在 Windows 本机执行；选型、安装和验证是后续任务。暂不增加用途重复的 ocr/read_pdf/read_docx 工具。
上传、下载、页面展示、SSE 传输由用户界面和 API 完成。Agent 使用已登记的文件/资料标识，不负责让用户文件从浏览器上传。
数据库、内存 Store、日志、LangSmith系统基础设施；不是给 Agent 自由操作的业务工具。
模型路由、检索轮数和调用预算运行配置与程序约束。上限由程序执行，Agent 可以知道剩余预算，但不能靠提示词自觉遵守，也不能自行提高预算。
大纲生成、角色识别、审美判断Agent 的推理/结构化输出任务；通过资料读取和模板结构提取获取依据，不确定时请求人工指导，不再套一个同名工具重复调用模型。
大纲确认、模板映射确认、正式状态提交由用户和 LangGraph 校验并提交。Agent可提出修改结果或通过后续真实人工反馈通道提问（工具形式待定），不提供绕过确认的任意写状态工具。
技能来源与执行当前固定skills/，无技能上传、市场或历史版本管理。Agent使用list_skills/read_skill，执行能力随运行时接入；未来市场为独立服务适配，不等于本地目录配置。
同义词扩展、提示词加载检索策略与资源管理。提示词放独立资源目录，专业词表可来自技能；不额外增加一个每次都必须调用的“同义词工具”。
技能脚本执行命令执行入口是运行时工具；底层进程执行模块是内部方法。优先复用已有执行能力，不强制新增 run_skill_script；读取与执行保持独立，脚本按技能步骤运行。

# 视觉识别模块（2026-11-05）

已实现独立模块及一个真实图片测试入口；不保留离线替身测试或独立示例。不是新增Agent工具或子Agent，尚未接入Harness、LangGraph、HTTP或自动渲染。原inspect_template行为不变。

## 怎么测试

真实集成验证（需要.env与可用模型，会消耗额度）：

```powershell
uv run --locked --no-sync python -m pytest tests/test_template_vision.py -s -q
```

默认读取data/vision-demo唯一PNG/JPEG。若要指定图片，在test_real_image_recognition中将调用改为await run_real_image_test(image=Path("实际图片路径"))；不支持命令行--image参数。读取LLM_BASE_URL、LLM_API_KEY、LLM_VISION_MODEL，视觉模型默认glm-5.3-flash。示例沿用原验证预算：120秒、4096输出token，max_retries=0；不是新增环境配置。未自动执行真实模型调用，等待用户对照截图验证。真实识别统一使用tests/test_template_vision.py。

PyCharm使用pytest运行配置，目标为tests/test_template_vision.py，在`result = await analyzer.analyze(...)`打断点，进入integrations/templates/langchain_template_vision.py查看请求构造与`response`。结果是Pydantic对象，可看result.page_role或result.model_dump()；只打印结果，不写入结果文件或覆盖截图。

## 文件和执行顺序

1. tests/test_template_vision.py：外层读取配置和图片、通过统一工厂创建模型、管理HTTP连接生命周期。
2. prompts/template_visual_analysis.md：可单独编辑的视觉任务规则。
3. domain/templates/template_vision_contract.py：约定analyze调用和TemplateVisionError；不依赖具体模型SDK。
4. integrations/templates/langchain_template_vision.py：接收已创建模型与提示词，把字节编码为data URL，构造SystemMessage与HumanMessage，等待一次响应，校验JSON。
5. models/templates/template_visual_analysis.py：统一定义输出字段。模型生成JSON，Pydantic校验；Schema通过消息提供给模型，不要求供应商原生结构化输出。
6. integrations/llm/langchain_model_factory.py：统一校验连接参数并创建ChatOpenAI，聊天与视觉共用。

依赖方向：适配器→协议/数据模型，示例→配置/适配器；数据模型不依赖执行层。model与HTTP客户端由调用方创建和管理；模块不关闭借入资源。不增加依赖或更改锁文件。BaseChatModel是SDK抽象，只在适配器中使用，不渗入业务协议。

## 输入输出与限制

输入image_bytes为原始图片字节，mime_type为image/png或image/jpeg。非空和MIME白名单检查不等于图像解码验证，当前不检查实际分辨率、文件签名或字节上限；调用方提供可信本地截图，正式上传需在上传边界增加检查。

输出各字段均必填，无默认值：page_role是cover/agenda/section/content/ending/unknown；role_evidence解释判断依据；visible_texts是可读文字列表；layout_description描述区域相对位置；main_colors是观察到的颜色；limitations是识别限制。列表可以为空，依据和布局描述不能为空。Pydantic拒绝额外字段，格式有效不代表判断正确。不保存模型原始回答、隐藏推理、用量或全局状态。

仅凭图片无法知道对象ID、占位符或可编辑性。截图与真实PPT页的对应关系由调用方维护，本模块不声称输入图片一定属于某页，不采用PPT内嵌缩略图。后续流程为inspect_template→可靠页面图片→本模块→Harness综合两种证据→必要时人工确认；当前尚未接线。

上游超时、连接与API错误转换成安全TemplateVisionError；格式无效也明确报错，不自动重复请求。任务取消正常传播。不记录包含图片和密钥的日志；本模块没有增加日志初始化。提示词可降低图片内指令的影响，但不承诺彻底消除提示注入。

## 统一模型工厂

所有ChatOpenAI实例只在integrations/llm/langchain_model_factory.py的create_langchain_model中构造。聊天的create_chat_client负责组装聊天适配器；视觉测试调用同一个模型工厂后组装视觉适配器。两种业务共享构造规则，但可传入不同模型名、超时和输出预算，不是强制共用同一个实例。

ModelConfigurationError也移到工厂模块，HTTP依赖从新位置导入。工厂不读取Settings、不发请求、不关闭借入HTTP客户端。模型重试固定为0，使用Chat Completions及http_socket_options=()，避免各入口连接选项不一致。没有新增环境变量、依赖或输出字段。

在PyCharm可直接点击test_real_image_recognition旁边的绿色图标选择Debug；pytest运行配置目标为tests/test_template_vision.py，附加参数-s，工作目录项目根目录。已移除独立脚本主入口，不使用Python模块运行配置或--image参数；pytest测试会发送真实模型请求。真实识别结果以本次实际调用为准；代码加载检查不表示模型识别通过。

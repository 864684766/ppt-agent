# 全系统日志使用说明

更新日期：2026-11-05。日志用于诊断已实现功能，不是Agent工具，不代表已经建设监控面板、告警或指标系统。

## 配置与文件位置

项目根目录.env：

```dotenv
LOG_LEVEL=INFO
LOG_OUTPUT=both
```

LOG_LEVEL必须大写：DEBUG、INFO、WARNING、ERROR、CRITICAL，默认INFO，保留选中级别及更严重记录。例如WARNING会过滤开始/完成摘要，但保留WARNING和ERROR。要查看完整执行过程，使用INFO或DEBUG。

LOG_OUTPUT必须小写：file仅文件、console仅控制台stderr、both两者；默认both。file/both保存到项目log/ppt-agent-YYYY-MM-DD.log，UTF-8、本地日期每日一个文件、同日重启追加、跨天首条记录自动切换。console不创建文件，也不删除历史文件；不按大小拆分或自动清理。

系统环境优先于.env，缺失使用默认值，空值或非法值由Settings报错。改配置后重启服务或重跑测试，不会自动热更新。本机常用INFO + both，需要逐页细节再用DEBUG；Docker可用INFO + console供容器平台收集。

## 看懂一条日志

```text
时间 | INFO | integrations.templates.pdfium_page_renderer | request_id=- | operation_id=操作编号 | event=completed operation=pdf.render duration_ms=123.45
```

| 字段 | 含义 |
| --- | --- |
| 时间、级别、模块名 | 何时、严重程度、由哪个Python模块记录 |
| request_id | 服务为每次HTTP请求生成的随机编号；独立测试没有HTTP请求时为“-”，不是业务会话 |
| operation_id | 每次被观测操作的随机编号，同一次操作的开始/完成/失败使用相同编号；外层无操作时为“-” |
| parent_operation_id | 开始事件中记录父操作编号，可串起HTTP→工具→适配器；无父操作为“-” |
| event | start开始、completed正常完成、failed失败、cancelled取消或流被关闭；其他名称为结果摘要 |
| operation | 开发者定义的固定操作名，如tool.search_web、web.search、template.convert_pdf、pdf.render |
| duration_ms | 从操作进入到退出的墙钟耗时，单位毫秒，包含网络等待或锁等待，不是纯CPU时间 |
| error_location | 异常类型与“文件名:行号:函数名”的链条，不含异常原文、源码、局部变量或绝对目录 |

失败示意：

```text
event=failed operation=web.fetch duration_ms=1500.00 error_location=WebpageReadError[http_webpage_reader.py:行号:read] <- ConnectError[第三方文件.py:行号:函数]
```

排查时先找event=failed或ERROR，用operation_id找同一操作，再用request_id找整个HTTP请求；有父操作时沿parent_operation_id查调用关系。一个错误跨工具和适配器传播时会在多个边界记录，用这些编号判断它们是否属于同一次失败。日志不是JSON文件，而是包含固定字段的可读文本。

Postman响应头X-Request-ID可与日志request_id对应。编号由服务生成，不采用客户端传入值。框架处理的404/422等错误会记录状态码；若未处理异常在发送响应头前交给外层Starlette错误处理器生成500，该500响应不保证带X-Request-ID，服务日志仍有请求编号和安全错误位置。

SSE通常先返回HTTP 200，随后模型仍可能失败，因此还要检查sse_error及model.chat_stream失败日志；不能只看HTTP状态。流式操作在消费结束时记录完成，主动关闭或取消记录cancelled，不逐token写日志。

## 后续功能如何接入

config/logging_config.py统一创建处理器；main.py的FastAPI lifespan初始化，tests/conftest.py在pytest会话开始时自动初始化，独立脚本由入口读取Settings并初始化。不在每个业务文件重复配置，也不在导入时创建日志文件。

```python
# 仅放在独立脚本入口；pytest会自动执行conftest，无需复制。
settings = Settings()
configure_logging(directory=PROJECT_ROOT / "log", level=settings.log_level, output=settings.log_output)
```

```python
import logging
from diagnostics.operation_logging import log_operation

logger = logging.getLogger(__name__)

@log_operation("固定模块.固定操作")
async def perform_operation():
    # 这里执行原操作。装饰器只观察，不修改返回值，不吞掉异常。
    # 只有确定安全的状态/数量才显式记录，不整体打印参数和返回对象。
    logger.info("event=result returned_count=%s", 3)
```

普通函数、协程与异步生成器均支持；wraps保留函数说明及签名供LangChain读取，@tool在上、@log_operation在下。需要手动覆盖某段资源操作时使用operation_scope(logger, "固定操作名")上下文管理器。不要把每个私有函数或纯校验都装饰一遍。

INFO记录生命周期和结果摘要；DEBUG记录页级细节；WARNING记录跳过、降级、上游状态及HTTP 4xx；ERROR记录失败及HTTP 5xx。异常使用safe_error_location提取安全位置，不直接logger.exception或打印str(error)，因为上游异常可能含请求正文和密钥。异常继续按原规则传播，取消不转成业务失败。

## 日志边界

不记录密钥、完整URL/查询串、请求和响应正文、资料文字、模型回答或图片base64。当前日志不提供对任意消息的自动脱敏；新增字段必须显式审查。应用DEBUG不会自动打开httpx/httpcore/OpenAI/LangChain的DEBUG请求转储，配置将这些SDK logger最低级别设为WARNING；SDK自有处理器及WARNING内容仍需按实际接入审查。

保留pytest/Uvicorn已有处理器，LOG_OUTPUT只管理本项目处理器；print、Uvicorn访问日志、独立logger和子进程不因此被接管。Uvicorn自己的访问日志仍可能显示请求URL，请勿把密钥放URL。调用链上下文可传入asyncio.to_thread；自行启动线程/子进程需要显式桥接，当前没有跨进程追踪。

每日文件方案用于单进程，不承诺多Worker安全写同一文件。磁盘写满、进程被强制终止或原生库崩溃可能没有完整结束日志；日志有助于定位，不保证所有故障都能写入。外部请求目前不是每次底层重试单独记录。未安装指标采集、监控面板、告警或全链路平台。
